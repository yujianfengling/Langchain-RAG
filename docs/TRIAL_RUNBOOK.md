## 0. 先分清两种数据（**最容易出错的地方**）

| | 演示数据 | 真实试用数据 |
|---|---|---|
| 用来做什么 | 给老师/评委演示、自己练手 | 真实学生用完之后的记录，**只此一份** |
| 数据目录 | `git_text_demo_data`（随便删） | `git_text_trial_data`（**备份，不要删**） |
| 账号 | `demo_*`（口令统一，可写文档） | 学生 `try01`…（口令另发，**不写文档**） |
| 课程名 | 带「(演示数据)」后缀 | 带「试用」字样 |
| 能不能混 | ❌ 演示账号不要进真实试用的班 | ❌ 真实学生不要用演示账号 |

> 一句话：**演示环境随便折腾；真实试用环境开跑后只允许"读"和"加数据"，不允许改配置。**

## 1. 试用前：启动与检查（约 15 分钟）

```powershell
cd E:\WORKBUDDY\Game\git_text

# 1) 自检（只读，不会在数据目录建表）
python tests\check_first_run.py          # 退出码 0 = 必需项齐全

# 2) 用【真实试用】目录启动后端（★ 不要用 .env 里默认的正式 data/）
$env:EDU_DATA_DIR="E:/WORKBUDDY/Game/git_text_trial_data"
$env:ADMIN_USERS="<管理员账号名>"          # 只有这个账号能签发教师邀请码
python -m uvicorn api.app:app --host 0.0.0.0 --port 8000

# 3) 前端（另开一个终端）
cd frontend; npm run dev                   # 学生/老师用 http://<本机IP>:3000 访问

# 4) 语音（可选，另开终端；只有要用语音才需要）
$env:SPEECH_STACK_DIR="E:\WORKBUDDY\Game\speech_stack"
E:\WORKBUDDY\Game\speech_stack\venv\Scripts\python.exe -m speech_service.server
```

**开跑前 4 项确认（缺一项就别开始）：**

```powershell
curl http://127.0.0.1:8000/api/health      # 看 data_scope.dir_name 是不是 git_text_trial_data
                                           # 看 capabilities.text.available 是不是 true
curl http://127.0.0.1:8100/health          # 用语音才需要：engines.asr 是 ready
node tests/e2e_first_use_walkthrough.js    # 电脑端闭环，应 56/56
node tests/e2e_responsive_walkthrough.js   # 三档屏宽，应 120/120
```

> 上面两条走查脚本**自己会写测试数据**，所以它们跑的是隔离目录；
> 跑完如果提示"拒绝执行"，说明后端不是隔离目录——**先别启动试用**。

## 2. 建试用班级（老师，约 10 分钟）

1. 管理员登录 → 「设置 → 教师身份」→ 生成**教师邀请码**（`T-` 开头，一次性）→ 私下发给上课老师。
2. 老师注册 → 「设置 → 教师身份」输入邀请码 → 出现「教师工作台」。
3. 「教师工作台 → 新建课程」：课程名统一写 **`数据结构（试用）`**。
4. 「班级管理 → 新建班级」→ 得到 **6 位班级邀请码** → 发给学生。
   ⚠️ 这个 6 位码是**班级邀请码**，和老师的 `T-` 开头**教师邀请码**不是一回事。
5. 「课程资料」上传本章讲义 → 等提示变成「课程知识库可用（已收录 N 份文档）」。
6. 「教案」写/生成一份并发布。
7. 「作业与练习」新建作业草稿 → **AI 出题时必须选「挂到草稿作业」**（不选只会预览、不写入）→
   确认题目数 > 0 → 发布。

**记录员请注意**：老师操作时**不要帮忙点**，卡住就记下"哪一步、界面原话、他怎么理解的"。

---

## 3. 学生加入（学生，每人 5 分钟）

1. 手机或电脑打开 `http://<本机IP>:3000`（老师用电脑；学生两种都行）。
2. 注册账号：统一用 `try01`…`try12`（口令由记录员另发）。
3. 「我的学习 → 我的课程」→ 输入 6 位**班级邀请码** → 加入。
4. 完成老师布置的作业（答错没关系，错题才有用）。
5. 「错题本」看错题 → 对 1 个错题点「去复习」走一次。
6. 「AI学习助手」至少问 3 个本章问题。
7. （可选）点录音提问——**手机语音目前只有浏览器宽度实测，真机请先由一名成员试一次**。

## 4. 试用后：导出匿名汇总数据（记录员，约 10 分钟）

```powershell
$env:EDU_TRIAL_PASSWORD="<老师账号口令>"     # 只为登录用，不会被打进文件
python tests\export_trial_data.py --username <老师账号> --class-id <班级ID> --out data\trial_export
```

- 默认**只导出班级级聚合**（参与率、知识点错误率、每日趋势），**不含学生姓名、联系方式、问答原文**。
- 需要按学生对分数时，再加 `--with-mapping` 生成「账号↔代号」表；
  ⚠️ 该文件**不要放进汇报材料**，只给老师内部核对。
- 导出目录里会有 `导出说明.md`，写明数据目录、班级、时间范围与口径提醒，写材料前先读它。

**同时开始人工记录（系统里没有的）**：前测分数、后测分数、反馈表、使用时长、异常情况。

**填结果** → `docs/TRIAL_RESULTS_TEMPLATE.md`。填写纪律：

- 只填真实收到的数据；**缺哪个格子就写"缺失"，不要估算**。
- 标明参与人数、完成率（完成人数/参与人数）。
- **不要把"自动评测 47/47""走查 120/120"写成"学习提升"**——那是链路验证，不是教学效果。
- 样本 <5 人时只报原始分数与人数，不写"提升率"、不写"显著提升"。

|---|---|---|---|---|---|

**只有"能复现的阻塞问题"和"明显统计错误"才修**，其余先记下来试用结束再评估。

常见故障与恢复：

| 现象 | 先做什么 | 恢复办法 |
|---|---|---|
| 页面打不开 / 转圈 | 看后端窗口有没有报错 | 重启后端（**同一个 `EDU_DATA_DIR`**，否则会读写到不同库） |
| 提问报"模型不可用" | `curl http://127.0.0.1:8000/api/health` 看 `text.available` | 检查密钥配置后重启后端；**不要**改为假装成功 |
| 出题报"课程资料为空" | 看「课程资料」的知识库提示 | 点「重建知识库」；仍失败就读提示里的原因 |
| 误删了数据 | **先停手** | 用开跑前的备份恢复：`data/trial_export/` 与 `git_text_trial_data/` 的副本 |

**备份纪律**：开跑前把 `git_text_trial_data\` 整个目录复制一份到别处（如 `git_text_trial_data_backup_<日期>`），
试用期间每天结束后再复制一次。
