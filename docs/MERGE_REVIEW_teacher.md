## 2. ⚠️ 合并前必须处理的安全问题（组员代码里）

`api/routes/teacher.py`（组员版）3 个接口**没有任何身份校验**，直接返回全体用户的学习画像。
而我们的试用方案（`docs/TRIAL_RUNBOOK.md`）要求后端监听 `0.0.0.0:8000` 让学生从局域网访问
→ **同一网络内任何人都能读取所有学生的学习风格、掌握度、薄弱点与反馈统计**。

- 复现：起后端后直接 `curl http://<主机IP>:8000/api/teacher/students`（不带任何 token）即返回学生列表。
- 与本项目既定原则冲突：`docs/PROJECT_STATUS.md` 写明"角色只由后端判定，所有越权判断都在服务端做"。
- **建议**：这 3 个接口保留功能价值、但必须补 `Depends(require_teacher)`，并把数据范围收到
  "该教师名下班级的学生"，而不是全体用户。合并时由我按这个口径实现，组员确认。

## 4. 组员的 RAG 优化（`d7ff751`）——**建议完整保留**

这是他实打实的工作，与教师端无关，改动集中在检索层：

- **中文词级分词**：BM25 支持 `BM25_TOKENIZER=word`（新增 `jieba` 依赖），缺依赖自动回退字符级

  向量库缓存与淘汰（`_evict_if_needed`/`invalidate`/`clear_all`）
- **嵌入容错**：批量失败重试 + 零向量兜底（`_embed_batch_resilient`）
- **切分与清洗**：窗口合并、小片段过滤、`clean_chunk_text`/`meaningful_char_count`
- **工程债**：`requirements.txt` 补上 `pytest`（仓库有 28 个测试文件却一直没声明测试框架）

合并时必须保证这些不被打架覆盖——这是**唯一需要逐文件人工合并**的部分（3 个 RAG 文件 + knowledge_service）。
