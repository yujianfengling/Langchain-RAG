# 收尾验收说明（2026-10-05）

项目：**RAG与LangChain融合的智慧教育系统** —— 基于课程资料的检索增强问答与教学辅助。

主线保留：① RAG 课程资料问答；② 教师 RAG 备课；③ 基于真实学习证据持续适应的 Agent。

## 一、启动方式（务必使用正确的数据目录与角色）

后端（单实例）：

- 只停本项目后端：按命令行精确匹配 '*uvicorn api.app:app*'，避免误停其他项目进程。
- 启动：使用 ProcessStartInfo 显式注入环境变量后启动
  '<venv>\Scripts\python.exe -m uvicorn api.app:app --host 127.0.0.1 --port 8000'，
  工作目录为仓库根：
  - EDU_DATA_DIR = 隔离数据目录（例如 D:\...\langchain-rag-work\demo_data）
  - ADMIN_USERS   = demo_admin
  - TEACHER_USERS = demo_teacher
- 角色优先级：ADMIN_USERS > TEACHER_USERS > 数据库角色（登录/注册返回**有效角色**）。
- 启动后核对：GET /api/health/ready 返回 retrieval_mode=hybrid_ready；
  external_capabilities 可看 LLM/检索/语音状态。
- **必须只有一个监听 :8000 的实例**：Get-NetTCPConnection -LocalPort 8000 -State Listen
  应只返回一个 PID（uvicorn 的 supervisor + worker 属正常）。重复实例会导致路由不一致
  （曾实测上传接口间歇 405）。
- 前端：开发用 Vite :3000（代理 /api → :8000）；生产构建后由后端在 :8000 直接提供 frontend/dist。

## 二、人工验收清单

1. RAG 提问与原文引用：进入「学习助手」→ 选课程 → 提问命中课程资料 → 展开「查看原文」
   核对真实片段；未命中时显示「课程资料中未找到依据」。
2. 教师生成/编辑/发布教案，学生查看：教师工作台 →「课程与备课」→ 进入课程 →「教案」→
   生成（核对「课程资料依据 / 查看原文」）→ 编辑保存为新版本 → 发布；
   学生在「我的课程 → 已发布教案」查看。
3. 答错与教师改判后 Agent 采用新证据：「学习安排」入口运行 Agent → 读取学习状态与薄弱点 →
   安排复习/讲解；学生答错或教师改判后再次运行，读到的是更新后的结论。
4. 计划提出、取消、确认与生效预算：/plan/adjustments/propose 提出 → reject 取消 →
   apply confirm=false 拒绝（409）→ apply confirm=true 应用；应用后每日预计耗时与任务日期
   符合每日预算与截止；不可行方案保持草案（DRAFT）。
5. 教师 1366/800px、学生 390px：教师端 800px 使用顶部紧凑导航（三个主入口：
   课程与备课 / 作业与批改 / 学情分析）；学生端 390px 助手气泡正文与引用原文充分使用宽度、无横向溢出。

## 三、本轮已实现能力

- 题目知识点归属：出题→入库→作答→掌握度→错题→复习→Agent 全链路按**每题自身**归属；
  无法可靠归属记为「待确认」，保留作答但不计入精确掌握估计；定向出题返回有效题数与
  不足原因，并给出重新生成/补充资料入口。
- 计划预算：新增计划生效前校验每日预算与教师固定截止；可调整任务重排、教师固定任务保留；
  不满足 → 草案（待确认），不作为生效任务进入首页；确认时核对当前约束，约束变化则拒绝旧方案。
- 交互：教师工作台收敛为三个主入口（班级/资料/教案进入课程内，学生明细从学情进入）；
  文件名单行省略 + Tooltip；上传/删除/可见范围/重建后自动刷新资料数量、知识库状态与下一步提示。

## 四、已知限制（如实保留）

- 模型生成质量：出题与讲解由 LLM 生成，**不保证百分之百正确**；定向出题可能整批无法归属
  （系统如实标为「待确认」，不强行套用目标标签，也不计入学情）。
- 检索相关性：相似度阈值未调整，可能召回「相关但不足以回答」的片段；界面按是否标注引用与
  是否检索到资料如实展示。
- 学习适应发生在**提示与策略层**：不训练、不更新模型权重，不宣称教学提升率。
- 既有归属修正只针对有明确修正记录的演示数据；历史复习任务按机制作废/迁移并保留原记录，
  不批量重标全部历史。
- 手机端仅优化留白与换行，未做信息层级重排。
- 收尾问题清单（未在本轮扩大范围）：教师菜单进一步细分、资料数量多端实时推送、
  文件名在极窄屏的展示策略。
