## 三、发现并修复的问题（都有复现步骤）

### 1. 上传资料后 AI 出题报「课程资料为空」——隐藏的顺序依赖

- **现象**：老师上传资料，列表显示「已就绪」，知识库提示却是「当前不可用」；点「AI 出题」报
  `课程资料为空，无法出题（请先上传课程资料并重建知识库）`。
- **复现**：新建课程 → 上传任意 Markdown → 不点「重建知识库」直接 AI 出题。
- **根因**：`upload_material` 只把文件落到学科目录，**没有建向量索引**；检索为空 → 出题失败。
  老师必须先手动点一次「重建知识库」，但界面上没有任何地方提示这个顺序。
- **修复**：`services/teaching_service.upload_material` 在上传成功后**自动构建课程知识库**
  （仅在尚未就绪时触发，避免每次上传都重复嵌入）；构建结果随响应返回
  （`kb_rebuild`），失败时前端如实提示，不静默。
- **验证**：走查中「上传后课程知识库自动可用（无需老师手动重建）」由 ✗ 变 ✓，随后 AI 出题 200 通过。

### 2. AI 出题不选"草稿作业"→ 题目只预览不落库 → 发布的作业是空的

- **现象**：新建作业 → AI 出题（没选「挂到草稿作业」）→ 发布被拒 `作业还没有题目，无法发布`。
- **复现**：新建作业草稿 → 点「AI 出题」→ 不选草稿作业 → 开始出题 → 发布。
- **根因**：「挂到草稿作业」字段写着"可选"，但**不选就真的不会写入任何作业**，界面上没有说明。
- **修复**：`AssignmentsPanel` 中该字段补充说明"不选择时只预览题目，不会写入作业——这样发布的作业会是空的"；
  生成结果区在不挂作业时显示橙色警告，明确告知"本次只是预览，题目没有写入任何作业"及补救方式。
- **验证**：走查新增两项断言「草稿作业里确实有题目（题目数 > 0）」「发布作业给学生」，均通过。

### 3. 学生答完作业，错题本/复习却是空的（学科未选 + 数据不刷新）

- **现象**：学生做完老师布置的 3 道题（有答错），切到「错题本」显示"暂无错题"，「复习安排」显示"暂无待复习的知识点"。
- **复现**：学生入班 → 作答并答错 → 切到「错题本」。
- **根因**（两层）：
  1. 「错题本/复习/掌握度」都按**当前学科**查询，而学生进页面时学科为空且不会自动选；
     只有在「掌握度」里有一句"请先在上方选择学科"，错题本连这句都没有。
  2. 页面数据是进入时加载的，**作答之后不会刷新**，所以即使选了学科也可能是旧数据。
- **修复**（`pages/StudentPage.tsx`、`components/StudentCourses/index.tsx`）：
  1. 首次进入自动选中"我加入的课程"对应的学科（取不到就保持原样，学生仍可手动选）；
     入班成功后也立即把学科切到该课程；
  2. 切到「今日任务/复习安排/错题本/掌握度」时重新拉取一次数据。
- **验证**：走查中两项由 ✗ 变 ✓；观察记录显示错题本有"你的作答"原文、复习任务"已合并 3 次"、掌握度"暂估 20%（0/3）"。

### 4. 两种"邀请码"容易混淆

- **现象**：教师邀请码（T- 开头，开通教师身份）与班级邀请码（6 位，学生入班）在界面上都只叫"邀请码"。
- **修复**：教师端统一叫"**教师邀请码**"并补一句区别说明（"与学生在「我的学习」页入班用的 6 位班级邀请码不是一回事"）；
  班级相关文案统一叫"**班级邀请码**"（班级管理、作业面板、学生入班框、教师工作台页脚）。
- **验证**：走查断言「两种邀请码的区别已说明」「班级邀请码文案一致」通过。

### 5. 教师端仍写着"创建课程会授予教师身份"（过期文案）

- **现象**：`TeacherPage.tsx` 新建课程弹窗底部写着"创建课程的同时会给你授予教师身份（由后端记录，可审计）"，
  与"创建课程不再授予身份"的实际行为**相反**。
- **修复**：改为"创建课程需要教师身份，但创建课程本身不会授予身份；教师身份只能由管理员开通，
  或凭教师邀请码在「设置 → 教师身份」自助开通。"
- **说明**：这是上一轮提权漏洞修复时漏改的文案，属会误导用户的错误陈述。

### 6. 学生首次进入停在「今日任务」，看不到"怎么加入课程"

- **现象**：新学生进入「我的学习」默认停在今日任务，空状态只说"今天没有安排任务"，没有指向入班入口。
- **修复**：今日任务空状态增加按钮「去「我的课程」用班级邀请码加入」，点击直接切到「我的课程」标签。
- **验证**：走查断言「首次进入时能一眼找到加入课程的入口」通过。

### 7. 部署文档里的第一条命令在默认 Windows 控制台上直接崩掉

- **现象**：新成员照 `docs/DEMO_GUIDE.md` 跑 `python tests/check_first_run.py`，
  在第 `[1/7] 运行环境` 就抛 `UnicodeEncodeError: 'gbk' codec can't encode character '✅'`。
- **复现**：在普通 PowerShell（默认 cp936 代码页）里直接跑该命令；用 `PYTHONIOENCODING=utf-8` 跑就不复现
  （所以之前一直没被发现）。
- **影响**：这是"另一名组员能否照着文档部署"的第一道门，直接崩会让人以为项目坏了。
- **根因**：脚本用 ✅/❌/⚠️ 打印结果，GBK 表示不了这些字符。
- **修复**：新增 `tests/_console.py` 的 `safe_console()`（**保留原编码、只把不可编码字符替换成 '?'**，
  避免旧终端里中文变乱码），在 `check_first_run.py`、`_isolation_guard.py`、`seed_demo_data.py`、
  `export_trial_data.py` 启动时调用；同时把关键 emoji 换成 `[OK] / [缺失] / [注意]` 这类 ASCII 标记。
- **验证**：修复后原样执行 → 退出码 0、7 项检查全部打印完整。

> 同一类问题的另一例：`tests/_isolation_guard.py` 的"拒绝运行"提示也曾因此在 GBK 控制台上崩掉，
> 退出码不是预期的 2（现已加回归用例 `test_refusal_survives_gbk_console`）。

### 8.1 做了什么

| 改动 | 说明 |
|---|---|
| 窄屏导航（≤900px） | 应用侧边栏换成「顶栏 + 抽屉」：顶栏有「☰ 菜单」与登录入口，抽屉里是同一份菜单 |
| 断点取 900 而非 768 | 800px 时侧边栏仍占 220px，把内容挤到 981px；切抽屉后 800px 全页面无溢出 |
| 精确定位要隐藏的侧边栏 | 原来的 `.ant-layout-sider { display:none }` 会**连带隐藏页面内部的 Sider**；现在只隐藏 `.app-sider` |
| 学习助手窄屏学科选择 | ChatPage 的「学科选择器」原本只在内部侧栏里 → 手机上被隐藏、发送按钮永久禁用。窄屏改为聊天区顶部一行（学科选择 + 新建 + 历史对话抽屉） |
| 窄屏弹窗与表格 | 弹窗 `max-width: calc(100vw - 24px)`，保证底部按钮可点；表格交给 antd 自带横向滚动 |

### 8.3 过程中修掉的真实问题

1. **手机上没有导航、也点不到登录**：≤900px 侧边栏被 `display:none`，而登录按钮在侧边栏里
   → 手机用户连登录都做不到（脚本第一次跑就卡在这里）。已加顶栏 + 抽屉。
2. **手机上无法提问**：学习助手的「学科选择器」只在 ChatPage 内部侧栏里，窄屏被一起隐藏
   → 发送按钮永久禁用。已把学科选择移到聊天区顶部。
3. **验证脚本自身的假通过**（记录下来避免下次再犯）：窄屏下标签会被 antd 收进「更多」下拉，
   直接点 `.ant-tabs-tab` 会点到被裁掉的隐藏标签上——点了但页面没切换；当时断言写的是
   "不包含『暂无错题』"，于是**假通过**。已改为走「更多 → 菜单项」并**要求正向证据**
   （必须出现错题本的卡片标题与作答内容）。
