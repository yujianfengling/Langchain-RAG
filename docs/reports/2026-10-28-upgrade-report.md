## 二、上下文预算（最新口径，前后不一致的说法以本节为准）

### 2.1 两层预算

1. **历史预算**：`min(0.35×窗口, 131072)`，最近消息 60% / 摘要 40%，摘要撞 95% 上限时裁半句。
2. **请求总预算**（收口新增）：先扣**输出预留**（本次 `max_tokens`，未知时
   `CHAT_OUTPUT_RESERVE_TOKENS` 默认 1024），再按明确优先级压缩输入。

### 2.2 压缩优先级与安全约束（2026-10-28 收口定稿）

可压缩的只有：工具描述 → 整项工具 → 工具结果内容 → RAG → 历史（整条丢最早的）→ 摘要。

**绝不裁剪**（截断等于改坏请求）：

- 当前问题
- 系统提示（里面是权限与硬性规则等协议内容）
- 工具定义的 JSON / schema / 工具名 / 必需参数 —— 只允许**缩短描述**或**整项移除工具**
- 工具结果**条目**（只截断内容），保证 `tool_call` / `tool_result` 配对完整

**超出可压缩范围时**：置 `too_long=True`，由调用方返回明确提示
（"当前问题与必要的系统指令合计已超出上下文窗口…"），**不强行发送被裁坏的请求**。
三条链路（chat 非流式 / chat 流式 / tutor Agent）共用同一套 `fit_request`。

> `MAX_TOOL_RESULT_CHARS = 12000` 只是**字符辅助上限**，token 份额（25%）才是主口径。

## 三、导入 / OCR（扫描教材提供的是"文字提取"能力）

### 3.1 机制

- 扫描件（PDF 无文本层）走本地逐页 OCR，引擎降级链 `rapidocr → liteparse → pytesseract`，
  全部缺失时**显式报错**而不是静默入库
- 页级缓存（key 含文件 SHA + 引擎 + DPI），中断可断点续跑；支持并发（默认 2、上限 3）
- 阅读顺序：RapidOCR 按行输出会打乱双栏，已加**栏间距聚类**还原（判断不出多栏则原样返回）
- 章节：扫描件走 OCR 行正则，文本层 PDF 走 TOC + 字号（**两路，不要说成三种都会命中**）
- 页码：只在标记 `page_base=0` 的 PDF 上 +1，旧索引与普通文档保持原值
- 空白页与识别失败**分开记录**（`cached / text / blank / failed`）
- 用户可见提示：`import_service._ocr_user_note()` 把"多少页识别出文字 / 哪些页空白 /
  哪些页识别失败 / 插图图表未理解"写入 **`job.warnings` 字段**

### 3.2 真实教材切片（24 页 / 33.6MB，隔离目录）

从 252 页 / 349.8MB 教材按"墨量"挑出 24 页（含 2 页章节分隔页）。**未重跑整本，未重建旧库。**

| 项目 | 结果 |
|---|---|
| OCR | 24/24 页有文字，**134.8s（约 5.6s/页）**，空白 0、失败 0 |
| 章节 | 正确识别 第2/3/4/7/8/9 章 及 第二篇/第三篇 |
| 页码 | 切片 1–24 连续无缺；**切片页码 ≠ 原书页码**（映射表已存档） |
| 检索抽查 | 3 个查询各命中 3 条，带"资料 + 章节 + 页码"前缀 |

### 3.3 OCR 能力的边界（重要）

扫描件 OCR 提供的是**文字提取**能力：

- **公式**：真实教材样本里数学符号基本丢失（24 页只出现 `≤ ≥ →`），关系代数符号未恢复
- **表格结构**：多列布局被拍平成碎片文本（如"块头/20180001/李勇/男…"），行列结构与顺序不保证
- **图表**：不理解，只取其中印刷文字；`ocr_stats.figures_interpreted` 恒为 `False`
- **双栏重排**：只在合成样本验证过，真实双栏教材未验证
- 上述限制已写进 `job.warnings` 与 `config/env.example` 的"已知边界"注释

> 关于"用户已看到"：`_ocr_user_note()` 只保证**写进了 `job.warnings` 字段**。
> 本轮**没有做浏览器实查**，因此不能说"用户已经看到提示"——前端是否展示需另行验证。
