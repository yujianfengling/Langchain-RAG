## 5. 失败原因分析

### 5.1 RAG检索 vs LLM生成失败区分

| 失败类型 | 表现 | 本次测试结果 |
|----------|------|--------------|
| **RAG检索失败** | 返回空文档或检索异常 | ✓ 未发生 |
| **LLM生成失败** | API认证错误或调用超时 | ✗ 发生（预期行为） |

### 5.2 本次失败原因

**失败类型**: LLM生成失败

**失败原因**: API Key为占位符 `your_api_key_here`

**错误详情**:
```json
{
  "error": {
    "message": "Authentication Fails, Your api key: ****here is invalid",
    "type": "authentication_error",
    "param": null,
    "code": "invalid_request_error"
  }
}
```

**结论**: 这是**环境配置问题**，不是代码问题。配置有效的API Key后即可正常工作。

## 6. 异常处理验证

### 6.1 异常捕获机制

| 异常类型 | 捕获位置 | 处理方式 |
|----------|----------|----------|
| API Key为空 | `llm/deepseek.py` | 抛出 `RuntimeError` |
| API认证失败 | `llm/deepseek.py` | 抛出 `RuntimeError` |
| LLM调用超时 | `llm/deepseek.py` | 抛出 `RuntimeError` |
| RAG检索失败 | `rag/rag_service.py` | 抛出 `RAGServiceError` |
| 服务层错误 | `services/ai_service.py` | 捕获并抛出 `AIServiceError` |
| 调用层错误 | `chat_service.py` | 捕获并抛出 `AIServiceError` |

### 6.2 错误传播链路

```
llm/deepseek.py (RuntimeError)
    ↓
services/ai_service.py (捕获 → AIServiceError)
    ↓
chat_service.py (捕获 → AIServiceError)
    ↓
api/routes/chat.py (捕获 → HTTP 500)
```
