## 3. 发现问题列表

| 编号 | 问题 | 严重程度 | 状态 |
|------|------|----------|------|
| BUG-01 | 知识库状态始终显示"未构建" | **高** | ✅ 已修复 |

### BUG-01 详细信息

**问题描述**: 知识库管理页面中，即使学科已经构建了知识库，状态标签始终显示"未构建"。

**根因分析**:
1. 后端 `/api/knowledge` 原返回格式: `{"subjects": ["id1", "id2"]}` (字符串数组)
2. 前端期望格式: `{"subjects": [{subject_id: "...", status: "..."}]}` (对象数组)
3. 前端显示逻辑: `status === 'ready'` 但后端返回的是 `'已构建'`，永远匹配不上

**影响范围**: 所有学科的知识库状态显示

## 4. 修复文件列表

| 文件 | 修改内容 |
|------|----------|
| `api/schemas/knowledge_schema.py` | 添加 `KnowledgeBaseItem` 模型，`KnowledgeListResponse` 改为对象数组 |
| `services/knowledge_service.py` | `list_knowledge_bases()` 返回包含 `subject_id` 和 `status` 的字典列表 |
| `api/routes/knowledge.py` | 更新注释 |
| `frontend/src/types/index.ts` | `KnowledgeBase` 接口添加 `status` 字段 |
| `frontend/src/components/KnowledgeManager/index.tsx` | 修复数据获取路径 `kbRes.value?.subjects`；修复状态显示判断 `status === '已构建'` |

## 5. 修复前后效果

### 修复前
- 知识库状态始终显示"未构建"（灰色标签）
- 用户无法知道哪些学科已经构建了知识库
- 后端返回字符串数组，前端无法正确解析

### 修复后
- 已构建的学科显示"已构建"（绿色标签）
- 未构建的学科显示"未构建"（灰色标签）
- 后端返回标准格式的对象数组，前端正确解析和显示
