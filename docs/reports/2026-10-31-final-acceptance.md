## 三、"0 命中"问题针对性核查结论（2026-10-31 上午）

**现象回顾**：10-30 深夜验收学科在"删除资料→自动重建"后，伴学检索三次 0 命中，
重启后端后恢复。

**本轮核查**（同一服务进程内、不重启，`acc-demo-1031` 隔离小样本，检索函数
`ai_service.retrieve_and_build_context` 直调 + API 全链路）：

| 步骤 | 结果 |
|---|---|
| 基线检索 | 命中 |
| 新增第二份资料后检索（剩余+新增） | 命中 |
| 删除一份后检索（剩余） | 命中 |
| 再新增后检索 | 命中 |
| **清空全部资料→重新上传→检索** | **命中**（且自动建页 2/2，取消账二次修复实战验证） |

**结论**：替换/删除/清库重建后，同一服务进程检索均正常，**"0 命中"未再复现**。
当晚 0 命中的根因未能在日志中留下直接证据（日志无检索空态告警），最可能路径是
"删除后内存缓存失效 → 并发线程在重建窗口加载了半成品索引并缓存"（现构建尾部已有
`_invalidate_memory_index` 兜底）。**按任务要求如实保留风险**：该问题定性为
"低概率并发窗口、重启可恢复、当轮已不可复现"，未宣称根因已修复；录屏脚本已注明
"资料存在却未命中=记录故障"。

**附带查明**（非回归）：迷你验收课件第 2 页内容（约 40 字）低于 `chunk_min_length=90`
被设计过滤，纯 RAG 检索不到；tutor 的**页面检索通道**（页面索引逐页文本）会兜底命中
（浏览器实测 FC-2026-88 可答）。真实课件页文本量大不触发。录屏提问已选第 1 页事实。
