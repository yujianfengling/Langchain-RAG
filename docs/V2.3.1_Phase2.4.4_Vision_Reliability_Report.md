### 2.2 新架构路径问题

**关键发现**: `DocumentConverter`的缓存在新架构路径中**未被使用**。

新架构流程:
```
PDF → ImageExtractor → ImageAdapter → MultimodalEnricher → Document
```

`MultimodalEnricher`直接调用Vision API，**不经过DocumentConverter的缓存**。

**解决方案**: 在`MultimodalEnricher`中添加独立的持久化缓存。

## 三、实现的可靠性增强

### 3.1 重试机制（model_service.py）

```python
VISION_MAX_RETRIES = 3
VISION_DEFAULT_TIMEOUT = 60  # 秒
VISION_RETRY_BACKOFF_BASE = 1.0  # 指数退避基数
VISION_RETRY_BACKOFF_MAX = 10.0  # 最大退避时间
VISION_RETRY_JITTER = 0.5  # 随机抖动范围
```

**重试规则**:

| 错误类型 | 是否重试 | 说明 |
|----------|----------|------|
| `requests.exceptions.Timeout` | ✅ 是 | 超时 |
| `requests.exceptions.ConnectionError` | ✅ 是 | 网络连接错误 |
| HTTP 429 | ✅ 是 | 请求频率超限 |
| HTTP 5xx | ✅ 是 | 服务端错误 |
| HTTP 400 | ❌ 否 | 请求参数错误 |
| HTTP 401 | ❌ 否 | 认证失败 |
| HTTP 403 | ❌ 否 | 权限不足 |
| `ValueError` | ❌ 否 | 业务错误 |

**指数退避算法**:
```python
backoff = min(
    VISION_RETRY_BACKOFF_BASE * (2 ** attempt) + random.uniform(0, VISION_RETRY_JITTER),
    VISION_RETRY_BACKOFF_MAX
)
```

示例:
- 第1次失败后: 等待 ~1秒
- 第2次失败后: 等待 ~2秒
- 第3次失败后: 不等待，直接失败

### 3.2 超时配置

**修改前**: 硬编码30秒
```python
response = requests.post(url, headers=headers, json=payload, timeout=30)
```

**修改后**: 可配置，默认60秒
```python
timeout = kwargs.get("timeout", VISION_DEFAULT_TIMEOUT)  # 60秒
```

超时逻辑统一在`ModelProvider._call_openai_compatible_api()`中处理。

### 3.3 持久化缓存（multimodal_enricher.py）

**缓存键设计**:
```
cache_key = MD5(file_content + provider_class + model_name + prompt_version)
```

**缓存内容**:
```json
{
    "cache_key": "212baedd...",
    "filename": "image.jpg",
    "model": "qwen-vision",
    "page_content": "图片描述...",
    "metadata": {
        "model_used": "qwen-vision",
        "vision_status": "success",
        "cache_prompt_version": "v1.0"
    },
    "created_at": "2026-08-05T10:15:00"
}
```

**缓存失效条件**:
1. 文件内容变化（MD5不同）
2. Provider或模型变化
3. Prompt版本变化（`VISION_PROMPT_VERSION`）
4. 缓存超过30天

**仅缓存成功结果**:
- ✅ `vision_status == "success"` → 缓存
- ❌ `vision_status == "failed"` → 不缓存
- ❌ `vision_status == "skipped"` → 不缓存

### 3.4 优雅降级

**成功时**:
```python
metadata["vision_status"] = "success"
metadata["vision_retries"] = 0
```

**缓存命中时**:
```python
metadata["vision_status"] = "cached"
metadata["vision_retries"] = 0
```

**失败时**:
```python
metadata["vision_status"] = "failed"
metadata["vision_error_type"] = "timeout"  # 或其他类型
```

**跳过时**（文件不存在、尺寸超限等）:
```python
metadata["vision_status"] = "skipped"
metadata["vision_error_type"] = "file_not_found"
```

### 3.5 日志增强

**日志格式**:
```
[Multimodal] Vision调用成功, image=xxx.jpg, model=qwen-vision, latency=4.05s, retries=0, caption_length=470
[Multimodal] Vision缓存命中, image=xxx.jpg, model=qwen-vision
[Multimodal] Vision调用失败, image=xxx.jpg, error_type=timeout, latency=60.00s, 降级为OCR fallback
[Multimodal] Vision结果已缓存, image=xxx.jpg, model=qwen-vision, cache_key=212baedd...
```

**不记录的敏感信息**:
- API Key
- Authorization请求头
- 完整请求参数

## 七、结论

### 7.1 核心问题解决

| 问题 | 解决方案 |
|------|----------|
| Vision API超时 | 重试机制（3次）+ 超时增加到60秒 |
| 重复调用 | 持久化缓存（MD5+Provider+Model+PromptVersion） |
| 无状态记录 | vision_status/vision_retries/vision_error_type元数据 |
| 无日志 | [Multimodal]格式日志含image/model/latency/retries/status |

3. 优雅降级已实现：失败不阻断PDF处理
4. 202个测试全部通过，无回归
5. 图片Document检索稳定
