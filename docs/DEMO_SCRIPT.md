# 现场演示路线（5–8 分钟）

> 目标：让评委在 8 分钟内看懂**这套系统和"用普通 AI 问答"到底差在哪**。
> **不要逐页介绍功能**——按"一条教学数据链"讲，每一段都指出"普通 AI 问答做不到的那一点"。

## 0. 演示前 3 分钟准备（后台做完，不要占用演示时间）

```powershell
# 用隔离目录起后端（演示数据与正式数据分开）
$env:EDU_DATA_DIR="E:/WORKBUDDY/Game/git_text_demo_data"
$env:ADMIN_USERS="demo_admin"
python -m uvicorn api.app:app --host 127.0.0.1 --port 8000
cd frontend; npm run dev
```

用 `tests/seed_demo_data.py` 一次性生成演示账号与演示班级（脚本会打印账号口令）：

```powershell
$env:EDU_DEMO_PASSWORD="demo-pass-123"
python tests/seed_demo_data.py --base http://127.0.0.1:8000
```

> ⚠️ **演示数据必须标注**：演示课程名统一带「(演示数据)」后缀，演示账号统一以 `demo_` 开头。
> 演讲时明确说一句："下面看到的所有课程、作答、错题都是演示数据，不是真实学生学习数据。"

## 1. 开场 30 秒（一句话讲清定位）

> "这不是一个'能回答课程问题的聊天机器人'。它把**老师布置 → 学生作答 → 机器判分 → 错题与复习 →
> 教师看到班级学情**串成一条链：老师下一步教什么，是由学生真实作答数据推出来的。
> 普通 AI 问答只能回答一个人当下问的那一句，它不知道你们班谁错了哪道题。"

## 2. 主线演示（约 4.5 分钟，5 个动作）

### 动作 1｜老师怎么"进来"，以及为什么不是谁都能当老师（30 秒）

- 用 `demo_admin` 登录 → 「设置 → 教师身份」→ 生成**教师邀请码**（T- 开头）。
- 一句话：**"教师身份是受控开通的**：要么管理员开通，要么凭这个一次性邀请码；注册一个账号自己建课是拿不到教师权限的——上一版这里有过提权漏洞，已经修掉并有测试固定。"
- 对比普通 AI 问答：那边没有"老师"和"学生"，只有"用户"。

### 动作 2｜老师把教材变成"可检索的依据"（60 秒）

- 教师账号 → 「教师工作台 → 课程资料」→ 上传本章讲义（**演示时直接上传，让评委看到状态从"处理中"变"已就绪"**）。
- 指一下知识库提示：**"上传后系统自动建好这门课自己的知识库；每门课一个独立知识库，互不串。**"
- 对比普通 AI 问答：通用模型不知道你这份讲义；这里所有回答都能追到这份资料。

### 动作 3｜出题：题目由资料生成，答案留在服务端（60 秒）

- 「作业与练习」→ 新建作业草稿 → **AI 出题（选上这份草稿作业）** → 看到 3 道题 → 发布给班级。
- 指出两点：
  1. "题目依据的是刚才那份讲义，不是通用题库；"
  2. "出题结果里**没有标准答案**——答案只在服务端，学生交卷前拿不到。"

### 动作 4｜学生端：作答 → 判分 → 错题 → 复习（90 秒）

- 切换到 `demo_s1`：「我的学习 → 我的课程」→ 输入**班级邀请码**（6 位，和教师邀请码不是一回事）→ 进入作答。
- 故意答错 1 题 → 立刻显示"回答错误"（**后端判分，不是前端对答案**）。
- 切到「错题本」：能看到错题、"你的作答"和正确答案。
- 切到「复习安排」：**"这次答错自动生成了复习任务，到期日是按记忆曲线往后排的，不是立刻重复——同一知识点多次错题会合并成一条。"**
- 切到「掌握度」：显示"暂估 20%，证据 0/3"，并写明口径：只有独立作答算证据，**看过答案之后再答不算**。
- 对比普通 AI 问答：那边没有错题本、没有复习安排，也不会区分"你是想出来的还是看答案抄的"。

### 动作 5｜回到老师：班级学情 + 下一步教什么（60 秒）

- 切回教师账号 → 「学情分析」→ 选本班 → 展示：参与人数/样本量、任务完成、**各知识点错误率**、常见错题（只有题干选项，没有答案）。
- 点「AI 解读」：**"解读只在程序算出来的数字范围内说话**；样本不够时它会直接说'数据不足，不建议下结论'，而不是编一个结论。"
- 下钻一个错误率高的知识点 → 相关课程资料 → 建议动作。
- 收尾一句：**"老师看到的不是报表，是'哪一段讲义需要重讲'。"**

## 3. 差异化收束（30 秒，务必说出来）

| | 普通 AI 问答 | 本系统 |
|---|---|---|
| 谁在用 | 一个用户 | 老师 / 学生角色分离，权限后端强制 |
| 依据 | 模型的通用知识 | 每门课自己的知识库，回答可追到原文 |
| 判分 | 无 | 后端权威判分，答案不下发到前端 |
| 记住什么 | 对话 | 作答证据 → 错题 → 复习计划 → 掌握度 |
| 给老师什么 | 什么都没有 | 班级级参与率、知识点错误率、常见错题、教学建议 |
| 结论口径 | — | 样本不足就不下结论，绝不编造提升率 |

## 4. 演示中最容易被问到的三件事（准备口径）

1. **"真有学生用吗？"**
   → 诚实回答：**还没有。** 自动评测 47/47、浏览器走查 56/56 只证明链路可用；
   真实教学效果要等小班试用（`docs/TRIAL_PACKAGE.md` 已写好，结果模板仍是"待试用"）。
2. **"数据是真的吗？"**
   → "刚才这一遍是演示数据（课程名带「(演示数据)」），但流程和判分都是真的后端的真实逻辑。"
3. **"能对外上线吗？"**
   → "还差两件事：**密钥轮换**（历史提交里出现过旧密钥，必须换掉才算能对外）和
   一次真实小班试用。"

## 5. 演示失败时的兜底（不要现场调试）

| 出问题 | 怎么办 |
|---|---|
| 模型不可用（`/api/health` 里 `text.available=false`） | 不要开始演示；先修密钥再演 |
| 出题慢 | 演示前预生成一次题目，现场讲"这一步刚才已经生成好了" |
| 网络问题 | 全程本机跑（127.0.0.1），不依赖外网，除了模型 API |
| 某个页面报错 | 记下 URL 与操作，**不要现场改代码**；用备用账号重走该步 |
