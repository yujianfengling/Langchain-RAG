## FIX-001｜6 个 E2E 验收脚本一启动就崩（`Cannot access 'page' before initialization`）

- 发现时间 / 发现人：2026-09-27，试用准备期自查（准备给项目组演示"怎么跑验收脚本"时发现）
- 现象：运行脚本后立即退出，报
  `ReferenceError: Cannot access 'page' before initialization`，连浏览器都没打开。
- 复现步骤：
  1. `node tests/e2e_voice_flow.js`
  2. 立即报上面的错（`e2e_teacher_flow.js` / `e2e_model_default.js` / `e2e_agent_flow.js` / `e2e_browser_check.js` / `e2e_real_flow.js` 同样）
- 影响范围：**6 个脚本全部无法运行**。这是试用/验收要用的工具链，属阻断；
  不影响线上功能本身（后端、前端都正常）。数据无影响。
- 根因：隔离闸门 `requireBackendIsolated(page, base, purpose)` 被放在 IIFE 第一行调用，
  但它接收 `page` 参数，而 `page` 是后面才用 `const` 声明的 → 暂时性死区（TDZ）直接抛错。
  （闸门是上一轮为"写入前拒绝"加的，当时只验证了 Python 脚本，没有实际跑过这 6 个 JS 脚本。）
- 修复：闸门改为不依赖 Playwright —— 用 Node 的 `fetch` 直接查 `/api/health`
  （`async function requireBackendIsolated(base, purpose)`），调用点去掉 `page` 参数。
  6 个文件同步修改。
- 回归结果：
  - 语法：6 个文件 `node --check` 全部通过；
  - 闸门仍有效：把脚本指向一个返回 `isolated:false` 的假后端 → **退出码 2**，打印"拒绝执行：…（正式目录）"；
  - 真实跑通：`tests/e2e_voice_flow.js` 在桌面 1440×1000 下 **22/22 通过**、在 390×844 下 **24/24 通过**；
    其余 5 个脚本可正常启动（本轮未逐一做全流程验收）。
- 未覆盖/遗留：其余 5 个脚本只验证了"能启动+闸门有效"，没有重跑它们的完整断言（不在本轮范围）。

## FIX-003｜合并远端"优化"后，AI 出题默认路径误报"课程资料为空"（合并引入的回归）

- 发现时间 / 发现人：2026-10-01，本地与远端合并（commit `9d360a6`）后的回归验证
- 现象：教师在「作业与练习」里**不填知识点**直接点「AI 出题」，接口返回
  `422 {"message":"课程资料为空，无法出题（请先上传课程资料并重建知识库）","error_type":"insufficient_evidence"}`，
  但课程资料明明已上传并"已就绪"、知识库也可用。
- 复现步骤：
  1. 教师上传课程资料 → 等状态变「已就绪」
  2. 新建作业草稿 → 点「AI 出题」，**知识点留空**，数量 3
  3. 接口 422「课程资料为空」；换成手动填一个知识点（如"二叉树"）再出题则正常
- 影响范围：**教师端出题的默认路径**（不填知识点 = 按资料重点出题）完全不可用；
  影响所有课程、所有教师。属阻断。已发布作业与学生作答数据不受影响。
- 根因（实测定位，不是推测）：
  - 不填知识点时，后端用**课程标题**作为检索 query（`assignment_service.generate_questions`）。
  - 合并进来的分块清洗（`clean_chunk_text` / `is_meta_wrapper`）会丢掉 `[来源: 文件名]` 这类
    元信息包装——**清洗本身是对的**（这些包装不该进上下文），但它同时削掉了分块与课程标题之间的
    字面重合，而本项目的课程标题里带有资料文件名后缀（如"数据结构与算法（走查 fxf0）"）。
  - 实测：`hybrid_retrieve("二叉树", …)` 在 0.5 阈值下 1 条命中；
    `hybrid_retrieve(课程标题, …)` 同一索引下 **0.5 阈值 0 条、0.0 阈值 1 条**。
    全局阈值 `SIMILARITY_THRESHOLD` 合并前后都是 0.5（未变），所以问题不在阈值，而在"查询词与分块的
    字面重合被清洗掉了"。
- 修复（保留组员的清洗，不做回退）：
  1. `rag/rag_service.py::retrieve_context` 增加可选 `min_score`：显式传入时覆盖配置阈值；
     不传时行为与原来完全一致（学生问答不受影响）。
  2. `services/ai_service.py` 新增 `retrieve_for_teaching()`：先按配置阈值检索，
     **为空时**放宽到 0.0 再检索一次，并如实返回 `relaxed: true/false`——
     降级不会被伪装成"严格命中"。
  3. `assignment_service.generate_questions` 与 `lesson_plan_service` 改用该方法；
     放宽后仍为空才报"课程资料为空"（知识库真的没有内容时提示照旧）。
- 回归结果：
  - `python -m pytest tests/ -q --ignore=tests/eval`：**621 passed**（含本次新增的 4 条固化测试
    `tests/test_rag_service.py::TestTeachingRetrievalFallback`：不降级 / 降级一次并标记 /
    真无资料时保持为空 / `min_score` 覆盖阈值）
  - 浏览器首次使用走查：**56/56 通过**，其中「AI 依据课程资料出题并写入草稿作业」实测
    `请求={"assignment_id":"…","count":3} 响应=200 生成结果：请求 3 道 / 实际 3 道`
  - 响应式走查：**134/134 通过**
- 未覆盖/遗留：放宽阈值只作用于**教师自己课程知识库**内的生成场景；
  学生问答仍严格走配置阈值（避免答非所问）。若某课程资料与标题完全无字面/语义关联，
  放宽后仍可能命中弱相关内容——此时出题质量取决于提示词约束"只依据给定资料命题"。

## FIX-004｜「学生画像」把内部 user_id 当学生名显示（合并进来的面板，教师认不出是谁）

- 发现时间 / 发现人：2026-10-01，给合并进来的 3 个学生接口补 pytest 时发现
- 现象：「学生画像」列表的"学生"一列显示 `user_bcbbada2de67` 这样的内部 id，
  教师看不出这是班里的哪个学生（同一行其它列都正常）。
- 复现步骤：
  1. 教师建课 → 建班 → 学生用班级邀请码入班
  2. 教师工作台 → 「学生画像」
  3. "学生"一列显示内部 id，而不是学生用户名/昵称
- 影响范围：**只影响"教师能不能用这个面板"**——数据本身正确，但认不出人就没法做个别辅导。
  不阻断其它功能。数据无误。
- 根因：后端 `/api/teacher/students` 返回里其实同时给了 `user_id`（内部 id）、`username`、`display_name`，
  是前端表格把 `dataIndex` 落在了 `user_id` 上直接渲染；详情卡标题也用了内部 id。
- 修复：
  - `frontend/src/api/teacher.ts`：`StudentSummary` 补上 `display_name` / `username` / `class_name` / `course_title`；
  - `frontend/src/components/Teacher/StudentsPanel.tsx`："学生"列改为 `display_name → username → user_id` 回退，
    详情卡标题改用同一个展示名（`user_id` 仍作 rowKey 与详情请求参数）。
- 回归结果：
  - `npx tsc --noEmit -p tsconfig.json`：通过；
  - 真实浏览器（1366px，用走查创建的真实教师账号）：学生画像首行为
    `resp_s_1366_158g 均衡型 0 1 40% 0 0 2026-10-01 10:32:46 查看画像`，
    脚本判定"是否出现内部 id（user_xxx）= false"。
- 未覆盖/遗留：窄屏（≤900px）下该面板未单独做"显示名"检查；面板本身在 390/800/1366 三档已无横向溢出。

### 同批修掉的脚本假失败（不是产品缺陷）
- 「800px：教师端『工作台』入口在可视区内」报 FAIL（不可见）。根因是脚本用 `has-text("工作台")` 做**子串**匹配，
  窄屏时全局抽屉里的「教师**工作台**」也被命中，而抽屉是 portal、在 DOM 里更靠后，`.last()` 取到的是抽屉里
  那个不可见的项。已改为**精确文本**匹配（`filter({ hasText: /^\s*工作台\s*$/ })`），1366px 不再受影响。
  同一轮给教师端补了「工作台」「学生画像」两个面板的检查（120 → 134 项）。
