1. 读赛方《赛题规则》《参赛说明》《典型案例说明》《字段说明》与交接文档，把三项任务要求映射到系统实际入口并逐项核对。
2. 搭建两套隔离验收环境（官方数据验收 8010/5180、换数据序列 8014/5184），数据副本与教师库均在仓库外 `E:/WORKBUDDY/Game/.accept-iso/`。
3. 并行三个子代理：教师盲测（只给正常入口+测试账号+一句话任务）、多视口视觉检查（1366×768 / 1920×1080 / 1000×768 / 125% 缩放等效）、官方数据独立复算（纯标准库脚本，不调用被测项目统计函数）。

5. 串数据检查：同一浏览器先用 B 留讲评卡，再切复用编号的 B2，验证旧记录不串；代码审计产品逻辑硬编码。
6. 修复 12 项确认缺陷（统计口径、串数据、误导文案、走不通的操作、视觉遮挡等），两个修复子代理并行闭环视觉/盲测类缺陷。
7. 最终构建复跑：tsc / eslint / build / 管线 pytest / 83 项浏览器回归 / 49 项工作流 / 换数据探针全套，全部通过。

## 2. 教师盲测与系统化检查

盲测任务原话：「明天只够讲两道题。请选好题，找一份学生答卷说明准备怎么讲，再找到能给这名学生用的教材例题或练习。」

- 三件事达成：默认 2 道（Q014/Q018）可实时切 3 道且 URL 同步；D01 原答卷步骤＋三评分点齐全；教材出处原页可打开。
- 盲测卡点（均已修复）：讲评卡环节序号被误读为题号；教材抽屉不能翻页到例题正文；可用题目清单不可点、无出处。
- 状态保持：返回后班级/测验/主题/比较口径/题量/选中位置全部保留。
- 系统化路径覆盖于 `frontend/e2e-teacher-regressions.cjs`（83 项）与 `e2e-teacher-workflow.cjs`（49 项）：切测验班级→讲评题量 3→2→柱条失分名单→学生原答卷→返回核对；档案→同类题→提交→只改中间步重提交→反馈随输入变化→「查看原答卷」「回看练习题」；教材目录/答卷双入口→搜索/章节选中/打开页码/关闭滚动恢复；无记录、待评分、真实零分、无共同题、连续快速切换、刷新、前进后退、请求失败与过期响应不覆盖新方案。
- 盲测曾单次报告「登录后页面漂移」，多轮复现未观察到，列为未确认项（见 §8）。
