## 2. 修改原因详解

### P1: RAG存储架构断裂（核心问题）

**问题描述：**
- `build_knowledge`使用ChromaDB内存存储
- `retrieve_context`使用FAISS磁盘索引
- 导致构建成功但无法检索

**修复方案：**
1. 重写`rag/vector_store.py`，将ChromaDB后端完全替换为FAISS后端
2. 提供`create_vector_store`、`load_vector_store`、`FAISSVectorStore`和`GlobalFAISS`类
3. 确保生成`index.faiss`和`index.pkl`文件
4. 添加向后兼容的包装函数`add_documents`、`similarity_search`、`get_retriever`

**关键代码变更：**
```python
# 新的FAISS向量存储实现

        self.documents = documents
        self.embeddings = embeddings
```

**修复效果：**
- 构建流程：`build_knowledge` → `create_vector_store` → 生成`index.faiss` + `index.pkl`
- 检索流程：`retrieve_context` → `load_vector_store` → 加载`index.faiss` + `index.pkl`
- 数据格式统一：两者都使用FAISS索引格式

### P2: Health检查import问题

**问题描述：**
- Health检查使用动态import，import失败时无法立即暴露问题
- 可能导致健康检查误报

**修复方案：**
1. 将动态import改为模块级import
2. 在模块加载时立即捕获import错误
3. 在健康检查中使用预导入的模块

**关键代码变更：**
```python
# 模块级导入（避免动态import）
_llm_available = False
_get_model_info = None
try:
    from llm import get_model_info as _get_model_info
    _llm_available = True
except Exception as e:
    logger.warning(f"LLM模块导入失败: {e}")

# 健康检查使用模块级导入
@app.get("/health")
async def health_check():
    if _llm_available and _get_model_info is not None:
        try:
            model_info = _get_model_info()
            services["llm"] = model_info.get("available", False)
        except Exception as e:
            ...
```

**修复效果：**
- import失败时立即在日志中暴露问题
- 健康检查更加可靠
- 同时添加了config状态检查

### P3: GlobalFAISS重复方法定义

**问题描述：**
- `vector_store.py`中的`GlobalFAISS`类有重复的方法定义（count、add_documents、similarity_search）
- 可能导致方法覆盖和不可预测的行为

**修复方案：**
1. 完全重写`vector_store.py`，使用清晰的类结构
2. `FAISSVectorStore`类：提供单个向量存储实例的操作
3. `GlobalFAISS`类：提供全局管理功能，无重复方法

**修复效果：**
- 代码结构清晰，无重复定义
- 每个类职责明确
- 易于维护和扩展

```python
if any(keyword in error_msg for keyword in ["LLM", "模型", "API Key", "API密钥", "Key未配置"]):
```

### P5: RAG检索失败静默返回空列表

**问题描述：**
- RAG检索失败时静默返回`[]`
- 无法追踪错误原因
- 可能导致LLM在无上下文情况下回答问题

**修复方案：**
1. 在`services/ai_service.py`的`get_rag_context`函数中，RAG检索失败时抛出`AIServiceError`
2. 在`chat_service.py`的`_retrieve_context`函数中，RAG检索失败时抛出`RuntimeError`
3. 在`chat_with_ai`和`chat_stream`函数中捕获异常并返回明确错误信息

**关键代码变更：**
```python
# ai_service.py
def get_rag_context(question, subject_id=None, top_k=5):
    try:
        context_docs = retrieve_context(...)
        return context_docs
    except Exception as e:
        error_msg = f"RAG检索失败: {str(e)}"
        logger.error(error_msg, exc_info=True)
        raise AIServiceError(error_msg)  # 不再静默返回空列表

# chat_service.py
def _retrieve_context(question, subject_id=None, top_k=DEFAULT_TOP_K):
    try:
        context_docs = retrieve_context(...)
        return context_docs
    except Exception as e:
        error_msg = f"RAG检索失败: {str(e)}"
        print(f"[ERROR] {error_msg}")
        raise RuntimeError(error_msg)  # 不再静默返回空列表
```

**修复效果：**
- RAG检索失败时记录详细错误日志
- 抛出明确异常，便于问题追踪
- 用户能够知道RAG服务出现问题
