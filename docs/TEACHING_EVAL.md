## 一、评测集与判分依据

| 项目 | 内容 |
|---|---|
| 课程章节 | 数据结构 · 二叉树（3 份固定材料：定义与性质 / 遍历 / 二叉搜索树） |
| 干扰材料 | 1 份与课程无关的英语写作资料（用于"加入无关资料后是否仍正确"的对照） |
| 评测集文件 | `tests/eval/dataset/eval_set.json`（每个样本都带判定依据，人工可复核） |
| 运行脚本 | `tests/eval/run_eval.py` |
| 账号 | 评测课程 1 门 + 1 位教师 + 每轮 3 个**全新**学生账号（账号名带运行编号，保证期望值与历史无关） |
| 数据范围 | **隔离数据目录**（脚本会拒绝在非隔离后端上运行） |

判分方式都是**程序可复核**的客观依据，不靠"看起来对"：

- RAG：必须命中要点关键词（每组至少一个）+ 引用必须能定位到期望的资料文件名；
  材料没有答案的样本，必须明确说明材料未覆盖，且**不得把材料里没有的内容说成课程依据**
  （补充课外常识必须标注为一般性/通用知识）。
- 教学闭环：判分结果、错题数、待复习数、掌握度是否有证据、学情样本量是否与数据库原始记录一致。
- Agent：以**工具调用记录**为证据（是否读取该生学习状态、是否做预算检查、
  改计划是否走 `propose_adjustment` 提议通道），不评判模型措辞。
- 语音：流程与耗时（含重复测量取区间），并导出音频供**人工试听**。

## 二、如何复现（约 10 分钟）

```powershell
# 1) 启动隔离后端（必须带初始教师，教师身份不再由建课自动授予）
$env:EDU_DATA_DIR="E:/WORKBUDDY/Game/git_text_e2e_data"   # 任意隔离目录
$env:TEACHER_USERS="eval_teacher"
python -m uvicorn api.app:app --host 127.0.0.1 --port 8001

# 2) （可选）语音链路：启动本地语音服务
$env:SPEECH_STACK_DIR="E:/WORKBUDDY/Game/speech_stack"
E:\WORKBUDDY\Game\speech_stack\venv\Scripts\python.exe -m speech_service.server

# 3) 跑评测（注意：本脚本进程的 EDU_DATA_DIR 必须与后端一致，否则会被拒绝执行）
$env:EDU_DATA_DIR="E:/WORKBUDDY/Game/git_text_e2e_data"
python tests/eval/run_eval.py --base http://127.0.0.1:8001

# 4) 查看结果
#    tests/eval/output/EVAL_REPORT.md     人读报告
#    tests/eval/output/eval_report.json   机器可读结果
#    tests/eval/output/listen/*.wav       语音样本（人工试听用）
```

按子系统单独跑：`--suites rag,loop,agent,voice`（可任意组合）。

| 语音端到端 | 识别 → 问答 1.65 s（不含朗读） |

## 四、典型问题与限制（如实记录）

1. **耗时会被 GPU 争用放大**：首轮全量评测中同一 TTS 接口出现过 RTF **17.3** 的离群值，
   单独复测为 **0.90–1.00**。因此评测脚本改为**重复 3 次取区间**，
   并建议评测时不要让其它 GPU 任务同时运行。这不是"音质问题"，但会直接影响体验。
2. **语音音质未通过人工验收**：程序只能验证流程、可懂度（ASR 回读）与耗时。
   **必须人工试听** `tests/eval/output/listen/*.wav` 后才能对音质下结论。
3. **RAG 会补充课外常识**：材料未覆盖时，模型会先说明"材料中没有"，再补充一般性知识
   （实测样本 rag-08 补充了 AVL/红黑树常识）。当前策略是**允许但要标注**；
   若教学上要求"只讲材料内容"，需要额外收紧提示词（属产品决策，非缺陷）。
4. **Agent 在明确目标下会直接生成计划**：学生主动提出"帮我复习"时，`create_plan` 会落库；
   但**改期类调整**走 `propose_adjustment` 提议、需学生确认后才生效。
5. **评测集的覆盖面有限**：8 个 RAG 样本、4 道题、1 个 Agent 目标、3 段语音，
   只能说明主链路可用，不能替代更大规模的抽样与真实班级试用。
6. **样本量阈值**：学情统计在"已判分作答 <5 次或参与学生 <2 人"时显示"数据不足"，
   因此小班/短周期试用时教师端不会给出知识点结论（这是有意的，避免用 1-2 条数据下结论）。

## 五、真实试用方案（**状态：待真实试用验证**）

> 下面的材料已备好，但**尚未有真实学生参与**。任何"提升了多少"的结论都必须来自真实试用。

### 5.1 试用任务（约 40 分钟/学生）

1. 用教师给的邀请码加入课程，完成教师布置的 1 次练习（4 题），查看自己的错题本；
2. 对至少 1 个做错的知识点，用「学习助手」生成一次复习安排（观察它是否要求你确认）；
3. 至少向 AI 提 3 个课程问题，判断回答是否有资料依据、引用能否找到原文；
4. （可选）试一次语音提问与朗读，填写试听感受；
5. 填写反馈表。

### 5.2 前后测方案

| 项目 | 设计 |
|---|---|
| 知识点 | 二叉树定义与性质 / 三种遍历 / 二叉搜索树查找与删除 |
| 题量 | 12 题（10 单选 + 2 简答，简答按评分要点人工判分） |
| 安排 | 前测（第 0 天）→ 使用系统学习 1 周 → 后测（第 7 天） |
| 控制 | 前后测**同难度不同题**；记录是否使用系统、使用时长 |
| 报告 | 只报告"参与学生的前后测变化 + 样本量"，并注明未使用系统的对照情况（如有） |

### 5.3 反馈表（学生填写）

| 问题 | 形式 |
|---|---|
| AI 回答是否解决了你的问题？ | 1–5 分 |
| 引用/来源是否能帮你找到原文？ | 1–5 分 |
| 错题本与复习安排对你有帮助吗？ | 1–5 分 |
| 语音朗读是否听得清、听得懂？（可选） | 1–5 分 |
| 最需要改进的一点是什么？ | 开放题 |

## 六、结论口径（避免误读）

- ✅ 可以说："功能链路按固定评测集 47/47 通过，样本 47 个，命令与数据都在仓库里可复现。"
- ✅ 可以说："首次使用体验走查（真实浏览器，教师+2 名学生完整闭环）56/56 项通过，脚本在 `tests/e2e_first_use_walkthrough.js`。"
  —— 但这是**脚本按固定路径跑出来的**，与"真实学生试用"是两回事。
- ✅ 可以说："教师布置 → 学生作答 → 判分/错题/复习/学情的数据是一致的，重复提交不会重复计数。"
- ❌ 不能说："教学效果已被验证"、"学生成绩提升 X%"——**没有真实学生数据支撑**。
- ❌ 不能说："音质已通过验收"——**尚未人工试听**（程序只验证了流程与可懂度）。
