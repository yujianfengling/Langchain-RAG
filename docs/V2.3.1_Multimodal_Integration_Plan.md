## 1. 当前问题分析

### 1.1 模块职责划分

V2.3.0 的 PDF 处理链路涉及四个核心模块，各自职责如下：

| 模块 | 职责 | 位置 | V2.3.0 状态 |
|------|------|------|-------------|
| **PDFAnalyzer** | 检测：从 PDF 页面识别元素边界和类型 | `rag/multimodal/pdf/analyzer.py` | ✅ 正常 |
| **ImageDetector** | 检测：定位图片位置、获取 xref/尺寸元数据 | `rag/multimodal/pdf/detectors/image_detector.py` | ✅ 正常 |
| **ImageExtractor** | 提取：从 PDF 中提取图片为 PNG 文件并记录路径 | `rag/multimodal/image/extractor.py` | ✅ 已实现，未集成 |
| **MultimodalDocumentConverter** | 视觉增强：调用 Qwen Vision 生成图片描述 | `rag/multimodal/document_converter.py` | ✅ 已实现，未集成 |
| **DocumentAdapter** | 生成 Document：将 PDFElement 转为 LangChain Document | `rag/multimodal/pdf/adapters/document_adapter.py` | ⚠️ image/table 缺陷 |

### 1.2 两条路径的断裂关系

```
路径 A（PdfLoader 生产路径）：
  PdfLoader.load()
    → PDFAnalyzer.analyze()
      → ImageDetector.detect()        ← 只获取 xref/尺寸，不提取图片文件
      → PDFElement(type=image, content={xref, width, height})
    → DocumentAdapter.adapt()
      → ImageAdapter.adapt()          ← 只生成 "[图片] | 尺寸: 898x401"
      → Document(page_content="[图片] | 尺寸: 898x401", metadata={type:"image"})
    → ❌ 无视觉增强、无 description、无 modality

路径 B（MultimodalDocumentConverter，设计但未集成）：
  MultimodalDocumentConverter.convert_elements()
    → ImageExtractor.extract()        ← 从 PDF 提取图片为 PNG 文件
    → MultimodalDocument(type="image")
    → multimodal_service.enrich()
      → QwenVisionProvider.analyze()  ← 生成 description
      → text_from_content()           ← OCR 文本
    → MultimodalDocument.to_langchain_document()
      → Document(modality="image", description="...", model_used="qwen-vision")
    → ❌ 未被 PdfLoader 调用
```

| # | 问题 | 影响范围 | 严重程度 |
|---|------|----------|----------|
| P1 | ImageAdapter 不调用 ImageExtractor，图片未从 PDF 中提取 | 146 个 image Document | 🔴 |

## 2. 设计目标

### 2.1 V2.3.1 核心目标

将路径 B 的视觉增强能力接入路径 A 的生产流程，使 PDF 中的所有元素类型生成统一的、可检索的 LangChain Document。

### 2.2 统一 metadata schema

所有 Adapter 输出的 Document 必须包含以下标准字段：

**注意**：DocumentAdapter 输出的是**中间态 Document**，包含基础 metadata（type, page, bbox, confidence 等），但缺少完整的多模态增强字段（modality, description, ocr_text, model_used 等）。**完整的 metadata schema 由 MultimodalEnricher 保证**，在 Enricher 阶段统一补充。

```python
{
    # 必填字段（所有类型）
    "type": str,           # "text" | "image" | "formula" | "table"
    "modality": str,       # "text" | "image" | "formula" | "table" | "mixed"
    "page": int,           # 页码
    "bbox": tuple,         # 边界框 (x0, y0, x1, y1)
    "confidence": float,   # 检测置信度
    "source": str,         # 文件路径
    "file_name": str,      # 文件名
    "file_type": str,      # "pdf"

    # 多模态增强字段（image/table 必填，text/formula 可选）
    "description": str,    # 视觉描述（image）或结构化描述（table）
    "ocr_text": str,       # OCR 提取文本（image）或完整表格文本（table）
    "model_used": str,     # 使用的模型名称（如 "qwen-vision"）

    # 类型特有字段（保持不变）
    "image_type": str,     # image: "raster" | "vector"
    "image_width": int,    # image
    "image_height": int,   # image
    "formula_type": str,   # formula: "display" | "inline"
    "is_inline": bool,     # formula
    "table_rows": int,     # table
    "table_cols": int,     # table
    "has_header": bool,    # table
}
```

## 3. 修改方案设计

### 3.1 三方案对比

#### 方案 A：ImageAdapter 内部调用 MultimodalDocumentConverter

```
PdfLoader
  → PDFAnalyzer → PDFElement
  → DocumentAdapter
    → ImageAdapter.adapt()
      → ImageExtractor.extract()           ← 新增
      → MultimodalDocumentConverter.convert_single()  ← 新增
      → Document(modality="image", description="...")
```

| 维度 | 评估 |
|------|------|
| 修改范围 | 仅修改 `ImageAdapter.adapt()`，约 50 行 |
| 架构合理性 | ❌ 违反单一职责：ImageAdapter 同时负责"适配"和"视觉增强" |
| 后续扩展性 | ❌ 如果未来 table 也需要视觉增强，需修改 TableAdapter |
| 风险 | 低：改动局部化 |
| 测试复杂度 | 低：只需测试 ImageAdapter |

#### 方案 B：DocumentAdapter 之后增加 MultimodalEnricher 阶段

```
PdfLoader
  → PDFAnalyzer → PDFElement
  → DocumentAdapter.adapt()                ← 保持不变
    → TextAdapter / FormulaAdapter / TableAdapter（保持不变）
    → ImageAdapter（改造：仅提取图片文件路径，不调用视觉模型）
  → MultimodalEnricher.enrich()            ← 新增阶段
    → 遍历所有 Document
    → image 类型：调用 Qwen Vision 生成 description
    → table 类型：调用 table_extractor 获取完整文本
    → 统一补充 modality 字段
  → 输出完整 Document
```

| 维度 | 评估 |
|------|------|
| 修改范围 | 新增 `MultimodalEnricher` 类 + 修改 `ImageAdapter` + 修改 `PdfLoader`，约 150 行 |
| 架构合理性 | ✅ 职责分离：Adapter 只负责格式转换，Enricher 负责内容增强 |
| 后续扩展性 | ✅ 新增元素类型只需在 Enricher 中增加处理分支 |
| 风险 | 中：需要修改 PdfLoader 流程 |
| 测试复杂度 | 中：需测试 Enricher + 集成测试 |

#### 方案 C：DocumentAdapter 整体升级为 MultimodalAdapter

```
PdfLoader
  → PDFAnalyzer → PDFElement
  → MultimodalAdapter.adapt()              ← 替换 DocumentAdapter
    → 内部集成 ImageExtractor + MultimodalDocumentConverter
    → 直接输出含 modality/description 的 Document
```

| 维度 | 评估 |
|------|------|
| 修改范围 | 重写 `DocumentAdapter` 或创建新类，约 300 行 |
| 架构合理性 | ⚠️ 过度设计：将所有职责合并到一个大类 |
| 后续扩展性 | ❌ 修改任何一个子功能都需要改动大类 |
| 风险 | 高：大规模重写，可能引入回归 |
| 测试复杂度 | 高：需要全面回归测试 |

### 3.2 方案比较总结

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 修改范围 | 小（~50行） | 中（~150行） | 大（~300行） |
| 架构合理性 | ❌ | ✅ | ⚠️ |
| 扩展性 | ❌ | ✅ | ❌ |
| 风险 | 低 | 中 | 高 |
| 测试复杂度 | 低 | 中 | 高 |
| 职责分离 | ❌ | ✅ | ❌ |

### 3.3 推荐方案：方案 B

**选择理由**：

1. **职责分离清晰**：Adapter 只负责"PDFElement → Document"的格式转换，Enricher 负责"原始 Document → 富化 Document"的内容增强。两者正交，互不耦合。

2. **扩展性最佳**：未来如果需要支持新的多模态类型（如视频、音频），只需在 Enricher 中增加新的处理分支。

3. **复用已有代码**：`ImageExtractor` 和 `MultimodalDocumentConverter` 已经实现，Enricher 只需调用它们。

4. **向后兼容**：TextAdapter 和 FormulaAdapter 不需要修改，它们输出的 Document 会被 Enricher 统一补充 `modality` 字段。

### 3.4 架构修正：MultimodalEnricher 所属目录

**原方案**：`rag/multimodal/enricher.py`

**修正方案**：`rag/enrichment/multimodal_enricher.py`

**修正理由**：
1. Enricher 不应只服务 PDF，未来需要支持 Word/PPT/图片上传等
2. 目录结构更清晰，Enricher 作为独立模块
3. 便于后续扩展其他类型的 Enricher

**目录结构**：
```
rag/
├── enrichment/                    # 新增目录
│   ├── __init__.py
│   └── multimodal_enricher.py    # 多模态富化器
├── multimodal/                    # 保持不变
│   ├── pdf/
│   ├── image/
│   └── ...
```

### 3.5 架构修正：调用链设计

**原方案**：DocumentAdapter 调用 MultimodalEnricher

**修正方案**：Loader 负责整体 pipeline 编排

**修正理由**：
1. DocumentAdapter 只负责 PDFElement → Document 的格式转换
2. Loader 负责整体流程编排，包括检测、提取、转换、富化
3. 职责更清晰，便于测试和维护

**修正后的调用链**：
```
PdfLoader.load()
  → PDFAnalyzer.analyze()
  → DocumentAdapter.adapt()
  → MultimodalEnricher.enrich()        ← Loader 调用，不是 DocumentAdapter
  → 输出完整 Document
```

### 3.6 架构修正：ImageExtractor 位置

**原方案**：ImageAdapter 调用 ImageExtractor

**修正方案**：PDF 处理阶段负责提取，Adapter 只负责转换 metadata

**修正理由**：
1. ImageAdapter 不应该依赖 PDF 文件
2. PDF 处理阶段负责 PDFElement + image_path
3. Adapter 只负责转换 metadata，符合单一职责原则

**修正后的流程**：
```
PdfLoader.load()
  → PDFAnalyzer.analyze()
  → ImageExtractor.extract()           ← PDF 处理阶段提取图片
  → PDFElement(type=image, content={..., image_path: "/path/to/image.png"})
  → DocumentAdapter.adapt()
    → ImageAdapter.adapt()             ← 只负责转换 metadata，不负责提取
  → MultimodalEnricher.enrich()
```

**ImageExtractor 接口设计**：
- **批量处理**：`extract(elements: List[PDFElement]) -> List[PDFElement]`
- 输入：PDFElement 列表（可能包含 text/image/table/formula 等类型）
- 输出：处理后的 PDFElement 列表，只处理 `type=image` 元素
- 对非 image 元素直接透传，不修改
- 好处：减少调用次数，便于批量优化，符合 PdfLoader 批量处理风格

### 3.7 架构修正：Table 增强方案

**原方案**：引入 Camelot/PDFPlumber 提取完整表格

**修正方案**：V2.3.1 暂不引入第三方表格解析

**修正理由**：
1. 优先使用 TableElement content → Document
2. 降低复杂度，聚焦核心问题
3. 第三方表格解析放到后续版本

**修正后的 Table 处理**：
```
TableElement.content
  → 直接使用 content（已是文本格式）
  → Document(page_content=table_content)
```

### 3.8 架构修正：测试验收标准

**原方案**：图片检索要求 100% 返回 image Document

**修正方案**：top-k 结果中至少包含 image 类型或包含 image description 语义

**修正理由**：
1. 避免误判，允许合理误差
2. 更符合实际检索场景
3. 降低测试复杂度

**修正后的验收标准**：
```python
# 图片检索测试
def test_image_retrieval():
    results = retrieve_context("这个实验装置图说明什么", subject_id="大学物理")
    # 方式1：top-k 结果中包含 image 类型
    image_results = [r for r in results if r.metadata.get("type") == "image"]
    # 方式2：top-k 结果中包含 image description 语义
    description_results = [r for r in results if "图片" in r.page_content]
    
    assert len(image_results) > 0 or len(description_results) > 0
```

## 4. 图片处理流程设计

### 4.1 完整流程（V2.3.1 Rev.3 架构）

```
PDF 文件
  │
  ▼
PdfLoader.load()
  │  1. 调用 PDFAnalyzer.analyze() → PDFElement 列表
  │  2. 调用 ImageExtractor.extract(elements) → 批量处理，仅对 type=image 元素
  │     └── 更新 PDFElement.content["image_path"]
  │
  ▼
DocumentAdapter.adapt()  ← 输出中间态 Document（基础 metadata）
  │  ├── TextAdapter    → Document(modality 缺失)
  │  ├── FormulaAdapter → Document(modality 缺失)
  │  ├── ImageAdapter   → Document(image_path 已填充)
  │  └── TableAdapter   → Document(content 直接使用)
  │
  ▼
MultimodalEnricher.enrich(documents)  ← 保证完整 metadata schema
  │  1. 统一补充 modality 字段
  │  2. 对 type="image" 的 Document：
  │     - VisionProvider.analyze_image() → description + ocr_text
  │     - QwenVisionProvider 作为具体实现
  │  3. 对 type="table" 的 Document：
  │     - normalize_table_content() → 确保 ocr_text/description
  │     - 支持 dict→Markdown, str→直接使用, 空内容→fallback
  │
  ▼
输出：完整 Document（可被 Embedding 和 BM25 检索）
```

**职责分离说明**：
- **PdfLoader**：负责整体 pipeline 编排，包括调用 ImageExtractor 批量提取图片
- **DocumentAdapter**：仅负责 PDFElement → 中间态 Document，输出基础 metadata
- **MultimodalEnricher**：负责保证完整 metadata schema，通过 VisionProvider 抽象调用视觉增强

### 4.2 图片临时文件管理

**提取位置**：`data/pdf_images/{pdf_filename}/{page}_{xref}.png`

**清理策略**：
- 构建索引时提取，索引构建完成后可选清理
- 缓存机制避免重复提取和分析
- 图片 MD5 作为缓存 key

### 4.3 缓存复用策略

**已有缓存**：`multimodal_service.py` 中的 `ImageDescriptionCache`

```python
# 缓存位置
data/cache/image_descriptions/{md5_hash}.json

# 缓存内容
{
    "description": "这是一个电路图...",
    "model_used": "qwen-vision",
    "timestamp": 1234567890,
    "image_size": {"width": 898, "height": 401}
}

# 缓存有效期：30 天
```

**复用方式**：MultimodalEnricher 直接调用 `multimodal_service.analyze_image()`，该函数内部已实现缓存逻辑。

### 4.4 错误处理

| 场景 | 处理方式 |
|------|----------|
| 图片提取失败 | 保留原始 page_content，metadata["description"] = "图片提取失败" |
| Qwen Vision 调用超时 | 重试 1 次，失败后使用 fallback：`"[图片] | 尺寸: {w}x{h}"` |
| Qwen Vision 认证失败 | 记录错误日志，使用 fallback |
| 图片尺寸过大 | 自动缩放至 MAX_IMAGE_DIMENSION（4096px） |

## 5. Table 处理方案

### 5.1 当前问题

TableAdapter 当前输出：
```
page_content = "[表格] | 尺寸: 5行x5列 | 页码: 8 | 预览: | 变量关系 | 内能增量ΔE | 热量Q | 功A"
```

**问题**：
- 预览文本可能截断（只取前 200 字符）
- 无完整表格结构化数据
- BM25 可以检索到部分关键词，但 Embedding 理解困难

### 5.2 升级方案（V2.3.1 Rev.3）

**V2.3.1 不引入 Camelot/PDFPlumber**，优先使用 TableElement content。

**MultimodalEnricher 对 table 类型的处理**：

```
TableAdapter 输出的 Document
  │
  ▼
MultimodalEnricher.enrich()
  │  检测到 type="table"
  │
  ▼
normalize_table_content(content)  ← 新增规范化层
  │  - dict 结构 → Markdown 表格
  │  - str 直接使用
  │  - 空内容 → fallback "| (空表格) |"
  │
  ▼
更新 Document：
  │  page_content = 规范化后的表格内容
  │  metadata["modality"] = "table"
  │  metadata["ocr_text"] = 规范化后的表格内容
  │  metadata["description"] = "表格内容"
```

### 5.3 输出格式

**Markdown Table 格式**（推荐）：
```
| 变量关系 | 内能增量ΔE | 热量Q | 功A |
|---------|-----------|-------|-----|
| 等体过程 dV = 0 | ΔE = νCvΔT | Q = νCvΔT | A = 0 |
| 等压过程 dP = 0 | ΔE = νCvΔT | Q = νCpΔT | A = PΔV |
```

**优势**：
- BM25 可以检索到表格中的关键词（如"等体过程"、"内能增量"）
- Embedding 可以理解表格的语义结构
- LLM 可以直接解析 Markdown Table

### 5.4 降级策略

V2.3.1 使用简化方案，无需降级策略：
- 直接使用 TableElement content
- 如果 content 为空，使用默认文本"空表格"
- metadata["ocr_text"] = table_content
- metadata["description"] = "表格：{rows}行x{cols}列，包含..."

**后续版本**：V2.4.0 可考虑引入 Camelot/PDFPlumber 进行更精确的表格提取，并添加降级策略。

```python
class MultimodalEnricher:
    """多模态 Document 富化器"""

    def enrich(self, documents: List[Document]) -> List[Document]:
        """对所有 Document 补充 modality 字段，对 image/table 进行内容增强"""
        for doc in documents:
            doc_type = doc.metadata.get("type", "text")

            # 统一补充 modality
            if "modality" not in doc.metadata:
                doc.metadata["modality"] = doc_type

            # 按类型处理
            if doc_type == "image":
                self._enrich_image(doc)
            elif doc_type == "table":
                self._enrich_table(doc)
            # text 和 formula 不需要额外处理

        return documents
```

## 附录 A：MultimodalEnricher 类设计

**文件位置**：`rag/enrichment/multimodal_enricher.py`

```python
"""
MultimodalEnricher - 多模态 Document 富化器

负责对 DocumentAdapter 输出的 Document 进行内容增强：
- image 类型：调用 Qwen Vision 生成描述
- table 类型：直接使用 TableElement content
- 所有类型：统一补充 modality 字段
"""

import logging
from pathlib import Path
from typing import List, Optional, Dict, Any
from abc import ABC, abstractmethod
from langchain_core.documents import Document

logger = logging.getLogger(__name__)


class VisionProvider(ABC):
    """视觉增强提供者抽象接口"""
    
    @abstractmethod
    def analyze_image(self, image_path: str) -> Dict[str, Any]:
        """
        分析图片并返回结构化结果
        
        Args:
            image_path: 图片文件路径
            
        Returns:
            包含 description, ocr_text, model_used 等字段的字典
        """
        pass


class QwenVisionProvider(VisionProvider):
    """Qwen Vision 提供者实现"""
    
    def __init__(self, timeout: int = 120):
        self.timeout = timeout
        self._service = None
    
    def _load_service(self):
        """延迟加载 multimodal_service"""
        if self._service is None:
            try:
                from services.multimodal_service import analyze_image
                self._service = analyze_image
            except ImportError:
                raise ImportError("multimodal_service 不可用")
    
    def analyze_image(self, image_path: str) -> Dict[str, Any]:
        """调用 Qwen Vision 分析图片"""
        self._load_service()
        return self._service(image_path)


class MultimodalEnricher:
    """
    多模态 Document 富化器

    在 DocumentAdapter 完成格式转换后，对 Document 进行内容增强。
    位于 rag/enrichment/ 目录，独立于 PDF 处理流程。
    """

    def __init__(self, enable_vision: bool = True, vision_provider: Optional[VisionProvider] = None):
        """
        初始化富化器

        Args:
            enable_vision: 是否启用视觉增强
            vision_provider: 视觉增强提供者（依赖注入），默认使用 QwenVisionProvider
        """
        self.enable_vision = enable_vision
        self.vision_provider = vision_provider
        if self.enable_vision and self.vision_provider is None:
            self.vision_provider = QwenVisionProvider()

    def enrich(self, documents: List[Document]) -> List[Document]:
        """
        对 Document 列表进行富化

        Args:
            documents: DocumentAdapter 输出的 Document 列表

        Returns:
            富化后的 Document 列表
        """
        enriched = []
        for doc in documents:
            try:
                doc_type = doc.metadata.get("type", "text")

                # 统一补充 modality
                if "modality" not in doc.metadata:
                    doc.metadata["modality"] = doc_type

                # 按类型处理
                if doc_type == "image" and self.enable_vision:
                    doc = self._enrich_image(doc)
                elif doc_type == "table":
                    doc = self._enrich_table(doc)

                enriched.append(doc)

            except Exception as e:
                logger.warning(f"Document 富化失败: {str(e)}")
                enriched.append(doc)

        return enriched

    def _enrich_image(self, doc: Document) -> Document:
        """对 image 类型 Document 进行视觉增强"""
        image_path = doc.metadata.get("image_path")
        if not image_path or not Path(image_path).exists():
            doc.metadata["description"] = "图片文件不可用"
            doc.metadata["ocr_text"] = ""
            doc.metadata["model_used"] = ""
            return doc

        try:
            result = self.vision_provider.analyze_image(image_path)
            doc.metadata["description"] = result.get("description", "")
            doc.metadata["ocr_text"] = result.get("ocr_text", "")
            doc.metadata["model_used"] = result.get("model_used", "")

            # 更新 page_content 为描述（可被 Embedding 检索）
            description = result.get("description", "")
            if description:
                doc.page_content = f"[图片] {description}"
            else:
                doc.page_content = f"[图片] 尺寸: {doc.metadata.get('image_width', 0)}x{doc.metadata.get('image_height', 0)}"

        except Exception as e:
            logger.warning(f"图片视觉增强失败: {str(e)}")
            doc.metadata["description"] = f"视觉增强失败: {str(e)}"
            doc.metadata["ocr_text"] = ""
            doc.metadata["model_used"] = ""

        return doc

    def _enrich_table(self, doc: Document) -> Document:
        """对 table 类型 Document 进行内容增强（V2.3.1 简化版）"""
        # 规范化表格内容
        normalized_content = self._normalize_table_content(doc.page_content)
        doc.page_content = normalized_content
        
        # 确保 ocr_text 字段存在
        if "ocr_text" not in doc.metadata:
            doc.metadata["ocr_text"] = normalized_content
        
        # 确保 description 字段存在
        if "description" not in doc.metadata:
            doc.metadata["description"] = "表格内容"
        
        return doc
    
    def _normalize_table_content(self, content) -> str:
        """
        规范化表格内容，支持多种格式
        
        Args:
            content: 表格内容，可能是 dict, str 或其他格式
            
        Returns:
            规范化后的 Markdown 表格字符串
        """
        if content is None:
            return "| (空表格) |"
        
        # 如果是字符串，直接使用
        if isinstance(content, str):
            return content if content.strip() else "| (空表格) |"
        
        # 如果是 dict 结构，转换为 Markdown 表格
        if isinstance(content, dict):
            try:
                headers = list(content.keys())
                if not headers:
                    return "| (空表格) |"
                
                # 构建 Markdown 表格
                header_line = "| " + " | ".join(str(h) for h in headers) + " |"
                separator = "| " + " | ".join(["---"] * len(headers)) + " |"
                
                # 获取数据行数（假设所有列长度相同）
                max_rows = max(len(v) if isinstance(v, list) else 1 for v in content.values())
                
                data_lines = []
                for i in range(max_rows):
                    row = []
                    for h in headers:
                        val = content[h]
                        if isinstance(val, list):
                            row.append(str(val[i]) if i < len(val) else "")
                        else:
                            row.append(str(val) if i == 0 else "")
                    data_lines.append("| " + " | ".join(row) + " |")
                
                return "\n".join([header_line, separator] + data_lines)
            except Exception:
                return str(content)
        
        # 其他格式，转为字符串
        return str(content) if content else "| (空表格) |"
```

```python
class ImageAdapter:
    """图片元素适配器（V2.3.1 改造）"""

    def adapt(self, element: PDFElement, source_path: Path) -> Document:
        """
        将图片元素转换为 Document

        V2.3.1 改造：
        - 仅负责转换 metadata，不负责图片提取
        - 图片提取由 PdfLoader 调用 ImageExtractor 完成
        - 视觉增强由 MultimodalEnricher 负责

        content = element.content
        width = content.get('width', 0)
        height = content.get('height', 0)

        # 获取图片路径（由 PdfLoader 提取后传入）
        image_path = content.get('image_path', '')

        metadata = {
            'type': 'image',
            'source': str(source_path),
            'file_type': 'pdf',
            'page': element.page,
            'bbox': element.bbox,
            'confidence': element.confidence,
            'file_name': source_path.name,
            'image_type': self._get_image_type(content),
            'image_width': width,
            'image_height': height,
            'image_xref': content.get('xref', 0),
            'image_size': width * height,
            # V2.3.1 新增：图片路径由 PdfLoader 提取后传入
            'image_path': image_path,
        }

        # page_content 暂时保留原始格式，Enricher 会更新
        page_content = f"[图片] | 尺寸: {width}x{height} | 页码: {element.page}"

        return Document(page_content=page_content, metadata=metadata)
```
