## 0. 一句话流程

老师用邀请码开通教师身份 → 建课建班 → 上传本章资料 → 发布教案与作业 → 学生用**班级邀请码**入班学习作答 →
老师看学情 → 第 7 天做后测 → 导出数据 → 填结果模板。

## 1. 参与人数与配置建议

| 项目 | 建议 | 原因 |
|---|---|---|
| 学生人数 | **6–12 人**（最少 5 人） | 少于 5 人时教师端学情会显示"数据不足"，无法验证知识点层面的结论；人数太多则人工记录负担过重 |
| 教师 | 1 人（**不要用参与开发的同学**，否则失去"第一次用"的检验意义） | 需要真实体验可行性 |
| 记录员 | 1 人 | 现场记异常、发问卷、收前后测 |
| 设备（推荐） | **每人一台电脑，屏宽 ≥1280px** | 1366×768 与 800px 都已实测无横向溢出；电脑端是主场景 |
| 设备（手机） | 学生端**可用手机**（390×844 已实测走通：登录注册→入班→作答→错题→复习→提问） | 见下方"手机端实测覆盖与限制"；教师端仍建议电脑 |
| 网络 | 学生机与服务器在同一局域网 | 只有模型调用需要外网 |
| 环境 | 一台上机跑后端+前端（老师机和学生机在同一局域网访问） | 见 `DEMO_GUIDE.md` 的启动步骤 |

### 1.1 手机端实测覆盖与限制（2026-09-27 实跑，脚本 `tests/e2e_responsive_walkthrough.js`）

**已实测可在 390px 手机宽度下完成**（真实浏览器 + 真实后端）：

| 步骤 | 实测结果 |
|---|---|
| 打开页面、注册/登录 | ✅ 顶栏有「登录 / 注册」，弹窗宽 374px 不超出屏幕 |
| 页面导航 | ✅ 顶栏「☰」打开抽屉，6 个页面都能进 |
| 入班（班级邀请码） | ✅ 输入框与「加入课程」按钮都在可视区内 |
| 查看作业、逐题作答 | ✅ 「进入作答」可点；作答弹窗 374px；3 道题都能提交并看到判分 |
| 错题本 / 复习安排 / 掌握度 | ✅ 标签收进「更多」下拉，点开后内容正常、页面不溢出 |
| 学习助手提问 | ✅ 选学科后发送按钮可用；**真模型回答成功返回** |

**手机上仍需注意 / 做不到的**：

- **教师工作台在手机上会横向溢出**（390px 下内容宽 512px）。教师端按"电脑为主"设计，**老师请用电脑**；学生端不受影响。
- 学习助手里放不下的标签/按钮会收进「更多」下拉，需要多点一下。
- 作业作答弹窗在手机上较长，需要上下滚动。
- **语音在手机宽度下已实测通过**（390×844：录音→转写→确认发送→逐句朗读→停止/暂停，24 项全绿），
  但用的是**假麦克风音频 + 移动宽度浏览器**，**没有真机验证**；真实手机麦克风/扬声器、iOS Safari/Android Chrome、
  权限弹窗与移动端自动播放策略均未验证。音质也未由人耳试听。若试用要用手机语音，**请先让一名成员用自己的手机试一次并记录**。
- 多人同时点朗读时本地语音服务会排队（实测出现过 502 语音服务正忙），建议一次只让一个学生点朗读。

## 2. 统一使用的课程章节（固定，便于横向比较）

**统一章节**：数据结构 —— **二叉树**（知识点：二叉树定义与性质 / 三种遍历 / 二叉搜索树查找与删除）

- 前测与后测都只考这三个知识点，**同难度不同题**。
- 上传的资料统一用一份讲义（`tests/eval/fixtures/` 下的样例讲义可直接用，或老师自备同章节讲义）。
- 不要中途换章节，否则前后测不可比。

## 3. 时间安排（建议 1 周，可按实际压缩）

| 时间 | 做什么 | 预计用时 |
|---|---|---|
| 第 0 天 | 前测（纸质或在线问卷，**不经过本系统**） | 学生 20 分钟 |
| 第 0 天 | 老师建课建班、上传资料、发教案与作业；学生入班 | 老师 25 分钟，学生 5 分钟 |
| 第 1–6 天 | 学生自定时间使用：AI 提问、做作业、看错题、按复习安排复习 | 学生每天 20–30 分钟，累计 ≥1 小时 |
| 第 7 天 | 后测（同难度不同题）+ 主观反馈表 | 学生 25 分钟 |
| 第 7–8 天 | 导出数据、填结果模板 | 记录员 60 分钟 |

## 4. 各方任务清单

### 4.1 老师（首次使用者，不要提前教他怎么点）

1. 拿到**教师邀请码**（由管理员在「设置 → 教师身份」生成，形如 `T-XXXXXXXX`）；
2. 注册 → 「设置 → 教师身份」输入邀请码 → 看到「教师工作台」出现；
3. 新建课程（名称统一：`数据结构（试用）`）→ 新建班级（如 `试用一班`）→ 把**班级邀请码**（6 位）发给学生；
4. 「课程资料」上传本章讲义（上传后系统会自动建好知识库，看到"课程知识库可用"即可）；
5. 「教案」→ 手写或生成一份教案并发布；
6. 「作业与练习」→ 新建作业草稿 → **AI 出题时务必选择「挂到草稿作业」**（不选只会预览、不写入作业）→ 发布；
7. 试用期间每天进「学情分析」看一眼，第 7 天导出数据。

> **记录员请在旁边记下老师卡住的每一步**（哪一步、界面原话、他当时的理解），这是最有价值的可用性证据。

### 4.2 学生

1. 注册账号（用户名统一 `try01`…`try12`，便于记录）；
2. 「我的学习」→「我的课程」→ 输入老师给的**班级邀请码**入班；
3. 完成老师布置的作业（至少一次，答错也没关系）；
4. 看「错题本」，对至少 1 个错题用「去复习」走一次复习；
5. 至少向「AI学习助手」提 3 个本章问题，判断回答有没有资料依据；
6. （可选）试一次语音提问与朗读，填写试听感受；
7. 第 7 天参加后测，填反馈表。

> 学生端不要手把手教；卡住的地方记下来（记录员不要代替学生点）。

## 5. 前后测评分规则

| 项目 | 规则 |
|---|---|
| 题型与分值 | 12 题：10 道单选（每题 6 分）+ 2 道简答（每题 20 分），总分 100 |
| 单选判分 | 机器判分（在线问卷）或人工对答案，全对得分、否则 0 分 |
| 简答判分 | **人工按评分要点**给分：要点齐全 20 分、缺 1 点 12 分、只答对概念 6 分、无关 0 分 |
| 前后测关系 | 同知识点、同难度、**不同题**；两卷评分标准同一份要点表 |
| 统计口径 | 只报告"参与学生的前后测得分变化 + 样本量"；**不换算成"提升率"**，除非样本 ≥5 且写明局限 |
| 剔除规则 | 后测缺考的、或使用时长 <20 分钟的学生单独列出，不混入平均 |

## 6. 主观反馈表（学生填，1–5 分 + 开放题）

| # | 问题 | 形式 |
|---|---|---|
| 1 | AI 回答是否解决了你的问题？ | 1–5 |
| 2 | 回答里的引用/来源能不能帮你找到原文？ | 1–5 |
| 3 | 错题本与复习安排对你有帮助吗？ | 1–5 |
| 4 | 你觉得这套系统比直接用普通 AI 问答好在哪？（可选） | 开放题 |
| 5 | 语音朗读是否听得清、听得懂？（没试过可跳过） | 1–5 |
| 6 | 最需要改进的一点是什么？ | 开放题 |
| 7 | 使用过程中有没有让你困惑或卡住的地方？ | 开放题 |

老师另填一列「老师版」：上课时是否愿意继续用？最想补的功能是什么？

|---|---|---|---|---|---|

## 8. 哪些数据自动导出、哪些必须人工记录

| 数据 | 来源 | 是否需要人工 |
|---|---|---|
| 参与人数、参与率、作答题次、已判分数 | **系统自动**（学情分析/导出脚本） | 否 |
| 任务完成人数/比例、各知识点错误率、常见错题、每日作答趋势 | **系统自动**（导出脚本） | 否 |
| 复习任务数量与完成情况 | **系统自动** | 否 |
| 前后测分数 | **人工** | 前测后测都在系统外做（纸质/问卷），按学生代号录入 |
| 主观反馈（1–5 分与开放题） | **人工** | 问卷回收后录入 |
| 使用时长 | **人工**（粗略计时） | 系统不记录"在线时长"，只记录行为事件，别把事件数当时长 |
| 异常与卡点 | **人工** | 见第 7 节 |

> ⚠️ **系统里"作答题次"≠"学习时长"，不要写成"学生平均使用 X 分钟"。**

## 9. 导出（去标识化）

```powershell
# 后端必须跑在隔离数据目录（脚本会自检，不满足直接拒绝运行）
$env:EDU_DATA_DIR="E:/WORKBUDDY/Game/git_text_trial_data"
$env:ADMIN_USERS="your_admin_account"
python -m uvicorn api.app:app --host 127.0.0.1 --port 8000

# 导出班级聚合数据（**不含学生姓名/联系方式/个人问答**）
$env:EDU_TRIAL_PASSWORD="<老师账号口令>"      # 只为登录用，不会被打印或写进文件
python tests/export_trial_data.py --username <老师账号> --class-id <班级ID> --out data/trial_export
```

导出内容：

| 文件 | 内容 | 是否可进汇报材料 |
|---|---|---|
| `班级学情_去标识化.csv` | 参与率、作答题次、完成情况等**班级级聚合** | ✅ 可以 |
| `知识点错误率_去标识化.csv` | 各知识点样本量/错误率（**不含学生姓名**） | ✅ 可以 |
| `每日作答趋势_去标识化.csv` | 每日作答与错误计数 | ✅ 可以 |
| `导出说明.md` | 数据目录、班级、时间范围、样本量、口径提醒 | ✅ 可以 |
| `学生代号映射.csv` | 仅 `--with-mapping` 时生成，含账号↔代号 | ❌ **不进汇报材料**，只给老师内部核对用 |

**去标识化规则**：默认只导出班级级聚合，从源头上不产生个人数据；
即使加 `--with-mapping`，文件里也只有"账号名 ↔ 代号"，不导出姓名、联系方式，也不导出学生的问答原文。
