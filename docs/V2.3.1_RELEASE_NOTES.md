**发布日期**: 2026-08-05

## 版本概述

V2.3.1 是智慧教育RAG系统的重要版本升级，实现了完整的 PDF 多模态处理能力。本版本在 V2.3.0 的多模态架构基础上，完成了生产级的功能实现和可靠性加固，支持从 PDF 中提取文本、公式、图片和表格，并集成了 Qwen Vision 进行图片理解。

## 主要功能

### 1. PDF 多模态处理 Pipeline

完整的 PDF 多模态处理流水线，支持从 PDF 中提取四种类型的文档：

| 类型 | 说明 | 输出格式 | 数量 |
|------|------|----------|------|
| **text** | 标准文本段落 | 纯文本 | 2196 |
| **formula** | 数学公式 | LaTeX 格式 | 570 |
| **image** | 嵌入图片 | 图片文件路径 | 146 |
| **table** | 表格数据 | Markdown 表格 | 6 |

**处理流程**:
```
PDF 文件
↓
PDFAnalyzer (pdfplumber) 识别元素类型
↓
文本提取 → 公式识别 → 图片提取 → 表格识别
↓
DocumentAdapter 统一转换为 Document
↓
MultimodalEnricher 增强处理
↓
Embedding 向量化
↓
FAISS + BM25 混合索引
```

### 2. Vision API 可靠性增强

#### 2.1 重试机制
- **策略**: 指数退避 + 抖动
- **次数**: 最多3次重试
- **间隔**: 初始1秒，最大10秒
- **触发条件**: 连接错误、超时、429、5xx错误

#### 2.2 超时配置
- **默认**: 60秒（可配置）
- **支持**: 单独配置超时时间
- **升级**: 从硬编码30秒改为可配置

#### 2.3 错误处理
- **超时**: `timeout`
- **认证**: `auth`
- **配额**: `quota`
- **网络**: `network`
- **通用**: `unknown`

#### 2.4 持久化缓存
- **缓存键**: MD5(provider + model + file_hash + prompt_version)
- **有效期**: 30天
- **存储**: `data/cache/vision/` 目录
- **格式**: JSON 文件

### 3. 表格结构化增强

#### 3.1 数据结构
```json
{
  "headers": ["列名1", "列名2"],
  "rows": [
    ["值1", "值2"],
    ["值3", "值4"]
  ]
}
```

#### 3.2 输出格式
- **page_content**: `表格内容:\n| 列名1 | 列名2 |\n| --- | --- |\n| 值1 | 值2 |`
- **metadata.description**: `表格(2行2列): 列名1, 列名2`
- **metadata.ocr_text**: 原始表格文本

### 4. 统一 Document Metadata Schema

```json
{
  "modality": "text|formula|image|table",
  "type": "text|formula|image|table",
  "description": "AI生成的描述",
  "ocr_text": "OCR提取的文本",
  "image_path": "图片文件路径",
  "vision_status": "success|cached|failed|skipped",
  "vision_provider": "qwen-vision",
  "vision_model": "qwen-vl-plus",
  "vision_latency_ms": 2070.8,
  "source": "文档来源",
  "page": 页码,
  "chunk_index": 分块索引
}
```

### 5. Formula Metadata 一致性修复

**问题**: FormulaAdapter 正确输出 `modality='formula'`，但 MultimodalEnricher 硬编码 `modality='text'` 导致覆盖。

**修复**: 在 `_enrich_text_document` 中检查 `type='formula'` 时保留 `modality='formula'`。

**验证结果**:
- Formula metadata: `type=formula, modality=formula` ✅
- 570 个 formula 文档全部正确 ✅
- 全部测试通过 ✅

## 架构流程

### 完整数据流

```
用户上传 PDF
↓
PdfLoader.load(pdf_path)
↓
PDFAnalyzer → ImageExtractor → DocumentAdapter
↓
MultimodalEnricher.enrich(documents)
↓
公式检查 → modality='formula'
图片增强 → description + ocr_text + image_path
表格增强 → description + ocr_text + markdown
文本增强 → modality='text'
↓
BatchedHuggingFaceEmbeddings.embed_documents()
↓
FAISS 索引 + BM25 索引
↓
HybridRetriever (FAISS + BM25 + Rerank)
↓
RAG 问答
```

### 组件职责

| 组件 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **PDFAnalyzer** | 识别 PDF 元素类型 | PDF 文件 | 元素列表 |
| **ImageExtractor** | 提取图片并保存 | 图片元素 | 本地文件路径 |
| **DocumentAdapter** | 统一文档转换 | 原始元素 | Document 对象 |
| **MultimodalEnricher** | 增强处理 | Document 列表 | 增强后的 Document |
| **BatchedHuggingFaceEmbeddings** | 向量化 | 文本列表 | 向量列表 |
| **GlobalFAISS** | 向量索引 | 向量 + 文档 | FAISS 索引 |
| **BM25Retriever** | 关键词检索 | 文档列表 | BM25 索引 |
| **HybridRetriever** | 混合检索 | 查询 | 排序结果 |

## 已知非阻塞事项

### 1. BM25 合理过滤

**现象**: BM25 索引缺少 9 个 Document。

**原因**: 这些文档都是单个希腊字母（γ、β、Δ），`_tokenize_chinese` 返回空 token，被合理过滤。

**影响**: 无实际影响，这些文档不适合 BM25 检索，但可通过 FAISS 向量检索找到。

**状态**: 已知行为，非缺陷。

### 2. LangChain 弃用警告

**现象**: 存在 2 个 LangChain 弃用警告。

**原因**: 使用了旧版 API，功能正常但建议升级。

**影响**: 不影响功能，仅控制台警告。

**状态**: 计划在后续版本处理。

### 3. Rerank 检索偏差

**现象**: 宽泛查询下，Reranker 可能优先返回文本而不是图片。

**原因**: Reranker 模型对文本相关性更敏感，图片依赖 description 匹配。

**影响**: 图片可能在宽泛查询中排名较低，但精确查询（如"电路图"）可正常检索到图片。

**状态**: 已知限制，可通过调整查询策略缓解。
